# <調査タイトル>

- 調査日: YYYY-MM-DD
- 調査手段: 例）Workflow による多面探索（Sonnet 収集・抽出 + Opus 統合）+ メインによる原文確認
- 問い: 何を確かめたかったか。1 文
- 対象セグメント: 誰の声を集めたか。隣接プロダクトの利用者を含むなら、どのプロダクトの利用者かまで書く
- 情報源: 使った情報源の種類（アプリレビュー / 掲示板 / X / Q&A / ブログ / GitHub Issue / 製品フォーラム）と言語

## 仮説と判定

事前に立てた痛みの仮説ごとに 1 項目。

### H1 <仮説の要約>

- 判定: 支持 | 反証 | 根拠弱い
- 根拠: どの声がなぜそう判定させるか。出典数を添える
- 反証にあたるもの: 仮説に反する声。見つからなければ「見つからなかった」と書く

## ニーズ一覧

クラスタごとに 1 項目。1 項目 = 1 つの困りごと。

### <クラスタ名>

- 場面: いつ・どんな状況で起きるか
- 困りごと: 何が困るか
- いまの回避策: いま何で済ませているか。我慢しているならそう書く
- 望む結果: どうなれば解決したと言えるか
- 強さの根拠: 痛みの強さを示す記述（頻度を表す言葉、金を払っている、使うのをやめた など）
- 出典数: N 件（重複しない出典の数。ユーザー数ではない）
- 代表的な声:
  - 「<原文のまま。要約も翻訳もしない>」
    - URL: <出典 URL>
    - 出典日付: YYYY-MM-DD（ページに記載がなければ「記載なし」）
    - 言語 / 情報源: 例）日本語 / App Store レビュー（<プロダクト名>）
    - セグメント: 誰の声か。隣接プロダクトの利用者ならそう書く
    - 確度: 高 | 中 | 低

## オーナーの観察との突き合わせ

- 一致: overview.md / experience.md に書かれた観察と重なるもの
- 食い違い: 観察と食い違うもの、想定より稀だったもの
- オーナーが挙げていなかったニーズ: 今回はじめて出てきたもの。どのクラスタか

## グレーゾーン・未確認

原文を開いて確認できなかった声（未確認）、情報源の偏り（言語・モダリティ・セグメント）、
支持も反証も見つからなかった仮説。「調べたが分からなかった」も明示的に書く。

## 影響する論点

この結果が効く open-questions.md の論点。overview.md（誰の何の困りごとか / 実在する痛みか）
や experience.md（想定ユーザーの広がり）のどこに関わるか。更新するかどうかはオーナーが決める。
