# english-opinion-trainer 引き継ぎ

- 作成日: 2026-09-10
- 引き継ぎ先: `tomada1114/nextjs-app-template`（Next.js 16 App Router テンプレート）をベースにした新規実装リポジトリ。リポジトリ名・作成の有無は未定。

## 何を作るか

英語で「自分の意見を短く伝える」ことに特化した、ブラウザで動くチャット専用の反復ドリル。対象はオーナー自身（他者に同じ痛みがあるかは未確認）で、対面の軽い問いや初対面のディスカッションで英語の意見がさっと出せない、という 3 場面の困りごとに当てる。既存の ChatGPT 直叩きや英会話・添削アプリ（Langua、スピフル、SmallTalk2Me、LangJournal ほか）はいずれも「構成テンプレート」「意見のタネ（ヒント）」「CEFR レベル別の言い直し」「ログインなしの即開始」を同時には満たしておらず、この 4 点の組み合わせで「構成支援つきの意見ドリル」という立ち位置を取る（競合調査 `research/competitors/_comparison.md`、2026-09-07）。

中核ループ: 現在の単元（組み立て方の単元コース、PREP → 譲歩型 → 比較型 → ミックス）の次のお題が、型（PREP / 譲歩型 / 比較型）とモード（短文 1〜2 文 / 長め 4〜6 文、単元コースが指定）つきで出る → ユーザーは英語のテキストで回答する（意見が浮かばなければボタンで「意見のタネ」3 候補〈切り口＋キーフレーズ 1〜2 語〉を出せる） → 回答 1 つに対して、選択したレベル（A2/B1/B2）に応じた決まった形式のフィードバックが JSON Schema 制約つきの構造化出力で返り、UI が描画する → 添削後の言い直しがカテゴリ・型のタグつきで「自分の言い回しリスト」にブラウザ内で溜まる。各単元は短文 8 問 → 長め 8 問の 16 問で修了し、お題はスキップ可能（一巡には数えない）。ログインなし、状態（レベル・表記言語・進度・言い回しリスト）はすべてブラウザ内保存。表記言語は英語既定で日本語に切り替えると UI とフィードバックが日本語になる（静的データは英語のみ）。1 回の利用はお題 1 つ単位で 5 分以内に完結する。

## 実装に効く決定

日付はいずれも decisions.md への記載日（2026-09-07、すべて同日）。

**体験・モードの骨格**

- 中核は「ランダムなお題に意見を出す一発の反復ドリル」。短文モード（1〜2 文）と長めモード（軽い日常の問いに PREP で 4〜6 文。IELTS Part 2 の 2 分独白ではない）の 2 モードを両方、最初の版から持つ。
- 1 回の利用は 5 分以内、お題 1 つ単位で完結する。
- モードはユーザーが選ばず、単元コースが指定する。お題グリッドの各セル（型 × カテゴリ）の 2 件を短文用 1 件・長め用 1 件に割り当て、お題ごとにモードを静的データで固定する。各単元は短文 8 問（この中でランダム）→ 長め 8 問（この中でランダム）の順で出し、16 問すべてにフィードバックが返った時点で修了。モードのユーザーによる上書きは不可。
- お題はスキップ可能だが、一巡の完了には数えず単元内で後に再出題する。
- 体系性は「組み立て方」の単元コース（単元 1 PREP → 単元 2 譲歩型 → 単元 3 比較型 → 単元 4 ミックス〈全お題ランダム〉）。単元内ではお題をランダムに出し、一巡するまで同じお題は出さない。進度としてブラウザ内に持つのは単元の進捗と修了のみで、ストリークやポイントは持たない。
- ループに残るのは、添削後の自分の一文を溜める「自分の言い回しリスト」（カテゴリ・型のタグつき、タネを使ったかどうかも属性として記録）。便利さの物差しは質（「さっと出せて、かつ伝わりやすいまとまった文章が書ける」）であり、タイムアタックは採らない。単元の進捗は動機づけであって上達の物差しではない。

**状態・表記言語**

- ログインなし。レベル・表記言語・進度・言い回しリストなどの状態はすべてブラウザ内保存。将来は外部システムで認証と DB を持てる構成にする。
- 表記言語は英語が既定。日本語に切り替えると UI もフィードバックも日本語になる。出力済みフィードバックの言語をその場で再生成することはしない。
- 静的データ（お題・タネ・テンプレート説明）は英語のみで持つ。日本語版は作らない。日本語切替で変わるのは UI とフィードバックだけ。

**テンプレートと問いの型**

- 構成テンプレートは PREP（意見→理由→例→意見）/ 譲歩型（相手の立場を認めてから自分の意見と理由）/ 比較型（A と B を並べて選ぶ理由）の 3 つ。どれを使うかはお題の「問いの型」に静的データで紐づき、アプリが「今回はこの型で」と提示する。ユーザーには選ばせない。
- 問いの型は 3 つ：おすすめ・意見系 → PREP、賛否系 → 譲歩型、二択系 → 比較型。
- 短文モードでは各型の先頭 2 要素だけを使う（フィードバックの判定も同様、下記）。

**意見のタネ**

- タネ 1 つは「切り口（立場）＋使えるキーフレーズ 1〜2 語」。完成した英文は入れない。1 お題・1 レベルにつき 3 候補（賛成・反対・条件つき など立場が分かれる形）。
- タネは最初は見せず、ボタンを押したときに出す。タネを使った回答とそうでない回答でフィードバックのプロンプトは変えない。タネを開いたかどうかは言い回しリストの属性としてブラウザ内に記録する（LLM には渡さない）。
- タネはお題ごと・レベルごとに事前一括生成した静的データ（実行時生成はしない）。

**フィードバック**

- フィードバックは固定 3 項目（伝わるか／直すべき 1〜2 箇所／レベル相応の言い直し）＋文法・語法の指摘、の JSON Schema で出力を固定し、UI 側が描画する。段階評価（スコア）は入れない。
- 「伝わるか」は、お題に紐づいた型の構成要素ごと（PREP なら Point/Reason/Example/Point、他 2 型も同様に固定キーで列挙）に 有／弱／無 の 3 値 enum ＋ 1 文の理由を返す。短文モードでは各型の先頭 2 要素だけを判定する。提示した型と違う組み立てで答えても、要素が拾えれば「有」とし、型からの逸脱そのものは減点・指摘しない。
- レベル（A2/B1/B2）が変えるのは、言い直しの語彙・構文の水準と指摘の厳しさのみ。お題自体はレベル間で共通。
- 指摘の件数上限・言い直しの長さの粒度はスキーマでは強制できない（`research/anthropic-structured-outputs.md`）。プロンプト指示＋事後検証で守る前提。

**お題・タネの量とベンダー**

- お題は 48 件（型 3 × カテゴリ 8 × 各 2 件のグリッド）。タネは 48 × 3 レベル × 3 候補 = 432 行。
- 実行時の LLM 呼び出しは「回答 1 つへのフィードバック」の 1 種だけ。エージェント構成（Agent SDK など）は採らない。
- 事前生成する静的データ（お題・タネ）は Claude Code に生成させる。検収は、偏りをグリッド仕様と機械検証（件数・重複・グリッドの埋まり具合をスクリプトで検証）で、質はお題 48 件全件目視・タネは各レベル 10 件抜き取りで行い、運用開始後は悪いお題・タネに印を付けて次の生成で差し替える（差し替え導線の実装は実装側に預ける）。
- LLM ベンダーは Anthropic に決定。SDK は Client SDK（`@anthropic-ai/sdk`）で Messages API を直接呼ぶ。Claude Agent SDK は採らない（エージェントループ・組み込みツール・セッション管理などをこの設計は 1 つも使わないため）。ただしベンダーを Claude に固定しているわけではなく、リポジトリ層（LLM クライアントの抽象）を分けてアダプタで差し替えできる構造にする、という抽象化方針は維持する。モデル（Haiku 4.5 か上位か）は未決のまま実装時に応答速度を実測して決める。
- 開発段階から従量課金の API キー＋少額の支出上限で進める。個人サブスク（Pro/Max など）を Agent SDK 経由で「ローカルなら無料」として使う前提は採らない。

**公開範囲**

- 「他人に URL を配るときのレート制限・入口」は最初の版の対象外。自分専用の間は自分の API キーを使い、支出上限は Anthropic のコンソール側で自分で設定する（default ワークスペースには上限を設定できないため、専用ワークスペースが要る）。

## 制約

- 1 回の利用はお題 1 つ単位で 5 分以内に完結する。
- 状態（レベル・表記言語・進度・言い回しリスト）はすべてブラウザ内保存のみ。ログイン・サーバー側保存は最初の版にない。
- 音声入出力なし。チャット専用（テキスト入力・テキスト表示）。
- 実行時の LLM 呼び出しは「回答 1 つへのフィードバック」の 1 種のみ。ベンダーは Anthropic、SDK は Client SDK（`@anthropic-ai/sdk`）。
- 開発は従量課金の API キー＋少額の支出上限で行う。default ワークスペースには上限を設定できないため専用ワークスペースを切ること。
- 静的データ（お題・タネ・テンプレート説明）は英語のみ。日本語切替で変わるのは UI とフィードバックのみ。
