## 何を作るか

Hintjump は、マウスに手を伸ばさず画面上の 1 か所をキーボードで押すための、macOS の常駐アプリ。
決まったショートカットを押すと対象の範囲にある押せる要素に英数字のラベルが出て、ラベルを打つとその要素が押されて終わる。
入口は 4 つで、すべて別のショートカット: アクティブウィンドウの左クリック、アクティブウィンドウの右クリック、メニューバー左(アプリのメニュー)、メニューバー右(ステータスアイコン)。
看板は「できるだけ絞って 1 文字ラベルで押せる」こと。入口を分けて対象を減らし、アクティブウィンドウでは押されやすい要素に 1 文字を優先して配る。
機能は「押す」ことだけに絞り、OSS・無料で、Homerow のクローンとは名乗らず別物として出す。LLM は使わない。
最初の利用者はオーナー本人。オーナーはトラックボール一体型のキーボードを使っており、現状はポインタを動かすほうが早い場面が多い。つまり速さと 1 文字ラベルは飾りではなく成立条件になる(experience.md「利用場面」)。

## 決まっていること

すべて 2026-09-21 の決定。理由と却下した案は decisions.md にある。

体験

- 入口は 4 つ、別々のショートカット: (1) アクティブウィンドウ × 左クリック、(2) アクティブウィンドウ × 右クリック、(3) メニューバー左、(4) メニューバー右。5 個以上には増やさない
- 動作は左クリックと右クリックだけ。修飾キーで動作を切り替える方式は採らない
- 「アクティブウィンドウ」の入口が対象にするのは、いま一番手前に出ているもの。開いているメニューや小さなパネルがあればそれを対象にする
- メニューやアイコンを押して何かが開いたあとは、macOS 標準のキー操作に任せる。開いたものにラベルを出し直す仕組みは持たない
- ラベルは英数字のみ。日本語入力での絞り込みや日本語ラベルには対応しない。まず英語圏に出す
- 利用者が英字入力(ABC)の状態で使うことを想定する。IME に依存しない仕組み(キーコード読み)も、入力ソースの自動切り替えも入れない。日本語 IME がオンのままだとラベルが打てないことは既知の制限として文書に書く
- アクティブウィンドウでは、押されやすい要素に 1 文字ラベルを優先して配り、残りは 2 文字にする。1 文字に使った文字は 2 文字ラベルの 1 文字目に使わない(例: 26 文字のうち 16 個を 1 文字に使うと、残り 10 × 26 = 260 個の 2 文字ラベルが作れる)
- 特定のアプリで無効にできる
- 設定はテキストファイル(ショートカット、ラベルに使う文字、除外アプリ)。他の人と共有しやすくするため
- 解析通信はしない。「通信ゼロ」は約束しない。更新があれば利用者に知らせ、何が変わったかを確認できるようにする
- 記録や統計は持たない(利用回数の表示はオーナーが取り下げた)

やらないこと

- スクロール、テキスト検索、連続クリック、⌘クリック、Mission Control、Dock
- ドラッグ、ホバー、コピー、マルチモニター対応
- ターミナルやエディタ内のリンク検出
- 覚えられるラベル(同じ要素に毎回同じラベルを保存して出す仕組み)。売りにもしない
- 画面内の範囲(左上など)で絞る入口。要素の種類で入口を分ける案も採っていない
- 効果音、テーマ、Hyperkey
- LLM

合格の基準と品質

- 合格の基準: オーナーが Homerow を止めて Hintjump だけで 1 週間過ごし、Homerow に戻らなかった
- 決定的に使わなくなる要因: ラベルが出るのが遅い / 押したい要素にラベルが出ない。ラベルの見やすさは大事だが最優先ではない
- 速さの目安: ショートカットを押してからラベルが出るまで 0.3 秒なら許せる。0.5 秒はモヤっとする
- 既存ツールで報告されている種類の不具合を、できるだけ出さないことを打ち出す

公開と土台

- アプリ名は Hintjump
- OSS・無料。見た目、用語、設定の構成、サイトの文言は独自にし、先行作への謝辞を書く。Homerow の設定画面や用語(Chain clicks など)をなぞらない
- 配布は Homebrew
- 土台は macos-app-template
- 実装と検証を始める時点で、オーナーは Apple Developer Program に加入済みである前提
- Electron 系(Claude Desktop、Slack)に対応できるかは、このリポジトリの最初の作業として実機で検証して決める

デザイン(2026-09-21 に決定。`design/` 配下)

- `design/design-concept.md` — 方向性と原則、参照にしたものと採否、ボイス&トーンと用語、なぞらない文言、決定ログ
- `design/design-system.md` — ヒント(ラベル)の書体・寸法・色・状態、配置規則、キー処理、チップ、ステータスアイコンとメニュー、状態ウィンドウ、実測コントラスト、実装セッションへの指示
- `design/wireframes.md` — 画面 W1〜W8(オーバーレイ 4 状態、ステータスメニュー、状態ウィンドウ、更新、端の状態)、フロー F1〜F9、横断仕様(タイミング、キー処理、状態一覧、文言表)
- 要点: ヒントは「標識」方向(黒タグに白文字、1 文字だけ赤みのオレンジ、角丸 4pt、尾なし、要素の左端に跨ぐ)。右クリック入口は抜きタグ + "Right click" のチップ。設定面はステータスメニュー + 状態ウィンドウ 1 枚(権限案内と兼用)。ヒントの配色は OS 外観に追従せず固定、状態ウィンドウはシステム部品とシステムカラーのみ

## 決まっていないこと

最初にやる検証(プロダクト側で行い、結果でオーナーが決める)

1. Electron 系で要素が取れるか。オーナーの Mac の Claude Desktop と Slack でアクセシビリティのツリーを読み、チャット部分やサイドバーの要素が取れるかを見る。取れるなら初版の対応範囲に入れ、取れないなら初版は「ネイティブ + ブラウザ」にする。Homerow は Slack では普通に動いた、というオーナーの観察がある(2026-09-21)。Claude Desktop は未再確認
2. 速さ。ブラウザと Electron 系の大きなツリーで、0.3 秒以内にラベルを出せるか
3. 「いま一番手前に出ているもの」(開いているメニューやパネル)を確実に判定できるか
4. 要素数と 1 文字率の実測。オーナーが日常で使うウィンドウに要素がいくつあり、実際に押したい要素が 1 文字の席(例: 上位 16 個)に入るか
5. App Sandbox を切る前提の確認。テンプレートは `App/MyApp.entitlements` でサンドボックスが有効。他アプリの要素を読んでクリックを合成するには切る必要がある、というのは当方の知識で未確認
6. 正規の署名で、アクセシビリティ権限がビルドや更新をまたいで保たれるかの確認。テンプレートの既定はアドホック署名(`CODE_SIGN_IDENTITY: "-"`)で、そのままだとビルドのたびに権限を付け直すことになる可能性が高い(当方の見立て。未検証)

プロダクト側で決めるもの(オーナーに選択肢と推奨を出して決めてもらう)

- 1 文字ラベルを配る優先順位の規則と、1 文字に使う個数。オーナーは「推測で決めていくしかない」と述べている。材料になる観察: ブラウザで押すのはリンク、ボタン、入力欄、タブ。Claude Desktop ではサイドバーの要素など。検証 4 の実測で確かめる
- 設定ファイルの形式。当方の推奨は TOML(手で書きやすくコメントが書ける)。弱点は Swift 標準に読み込みが無いこと。テンプレートは依存ゼロの方針なので、依存を足すか自作するかも含めて決める
- 更新を知らせる仕組み。(a) Homebrew に任せてアプリ内には変更履歴だけ持つ、(b) アプリ内更新の定番フレームワークで静的な更新情報ファイルを見に行き Homebrew と併用する。当方の推奨は (b)。オーナーは「どっちでもいい」「簡単に、API を使わずにできるなら自動アップデートが嬉しい」
- 4 つのショートカットの既定のキーと、ラベルに使う文字の既定値。他のアプリと衝突しない値を選ぶ
- デザインの小さな未決(open-questions.md): ヒントの大きさを設定で変えられるようにするか / 設定ファイルの自動再読み込み / ログイン時に起動 / ステータスアイコンのグリフ / オーバーレイを画面共有から隠すか

オーナーの確認が残っているもの(オーナーが実装前にやることの一覧は `owner-todo.md`)

- GitHub のユーザー名 / 組織名、ドメインの確保。オーナーが行う。商標データベースへの照会はしていない

未決のまま残るもの

- オーナー以外に同じ痛みがあるか。材料は集まったが結論は出していない
- 売りの伝え方。「入口を分ける」「押されやすい要素が 1 文字」を説明文と動画 1 本でどう伝えるか。オーナーは工夫が必要と述べている

## 制約

- 署名と公証: 公開リリースと Homebrew への登録には、Developer ID での署名と公証が必要(テンプレートの `docs/distribution.md`。Homebrew が未署名・未公証の cask を削除するという記述もそこにある。Homebrew 公式での確認は未了)。オーナーは実装開始までに Apple Developer Program に加入する
- 配布: サンドボックスを切る前提のため、Mac App Store では配れない見込み。公証付きの直接配布と Homebrew
- 権限: アクセシビリティ権限が必須。初回起動時の案内が要る
- 通信: 解析通信は入れない。通信するのは更新の確認だけにとどめる
- 調査の安全: 発行元を特定できないホストを直接取得しない。ドメインの状況は DNS 照会だけで見る。2026-09-21 に名前調査でウイルス対策ソフトがダウンロードを隔離した経緯がある(braintrust の `.claude/skills/_shared/safe-fetching.md`)
- 先行作への敬意: Homerow の見た目、用語、設定の構成、文言をなぞらない。ラベルを出して打つ方式そのものは Vimium 以来のジャンルで、採ること自体は問題ない
- 運用: 「特定のアプリで動かない」という報告が継続的に来る領域。一人で追える範囲を決めておく。macOS の更新で壊れる可能性がある
- テンプレートの門: ロジックは Core 側に置き、カバレッジの門(Core のみ)を保つ。ラベルの割り当て、優先順位、キー入力の状態遷移は Core に置ける。アクセシビリティの読み取りとクリックの合成は、Core でも UI でもない層として足す
