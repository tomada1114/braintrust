# Hintjump ワイヤーとフロー

作成: 2026-09-21。対象は macOS 常駐アプリ Hintjump。製品の枠と決定は `../handoff.md`、
中核の体験は `../experience.md`「中核の体験」にある。ここでは繰り返さず、画面とフローだけを描く。
寸法・色・状態の値は同じディレクトリの `design-system.md`(「ヒント部品の寸法」「バリアント」
「配置規則」「チップ」「ステータスアイコン」「状態ウィンドウの部品」)にあり、この文書では繰り返さない。

---

## 0. 凡例

| 記法 | 意味 |
|---|---|
| `[A]` | 1 文字ヒント・塗り(オレンジ面)。左クリック入口 |
| `[FJ]` | 2 文字ヒント・塗り(暗い無彩色の面)。左クリック入口 |
| `(A)` `(FJ)` | 抜きヒント(白い面 + 縁)。右クリック入口 |
| `[f J]` | 1 文字目を打った後。小文字 = 薄くなったその字。残り 1 文字はそのまま |
| `⟨ Right click ⟩` | チップ(mode chip / notice chip) |
| `·` `[·]` | アイコンの置き場所。絵柄は描かない |
| `______` | テキスト入力欄 |
| `(v)` `(x)` `(!)` | 状態ウィンドウの状態アイコン(checkmark.circle / xmark.circle / exclamationmark.triangle) |
| `>` `v` | 開閉(disclosure)の閉じ / 開き |

- 箱罫線(`┌─┐│└┘`)の枠は**アプリのウィンドウ**。W4a / W4b だけは画面上端のメニューバーの帯を表す
- ヒントは**対象の左辺を跨ぐ**(左半分は要素の外、右半分は要素に重なる)。ASCII では、
  ヒントと対象のあいだに空白を置かないことで跨ぎを表す(ヒントの `[` が対象の 1 文字目の 1 列左に来る)
- `[f J]` は打った字を示すための表記で、実際のタグの幅は変わらない(`design-system.md`「バリアント」)
- 大きさ・色・余白はすべて `design-system.md` にある。この文書では一切繰り返さない
- ヒントの文字は**例示**。どの要素に 1 文字を配るかの規則は未決
  (`../open-questions.md`「1 文字ラベルを配る優先順位の規則」)

## 1. 画面

### W1 ウィンドウ左クリック入口

登場フロー: F2 / F3 の 2 手目。
この画面の役割: 手前のウィンドウの押せる要素すべてにヒントを出し、打つ 1〜2 文字を選ばせる。

```
┌────────────────────────────────────────────────────────────────────────────────────────┐
│ · · ·                          Hintjump Docs - Triggers                                │
├────────────────────────────────────────────────────────────────────────────────────────┤
│ [FA]· [FS]· [FD]· [FG]· [FH]· [FJ]·     [WA]______________________________________     │
├────────────────────────────────────────────────────────────────────────────────────────┤
│ [A]Docs    [S]Reference    [D]Changelog    [U]+                                        │
├─────────────────┬──────────────────────────────────────────────────────────────────────┤
│  Docs           │                                                                      │
│                 │  Triggers                                                            │
│ [G]Overview     │                                                                      │
│ [H]Install      │  Hintjump has four triggers. Each one covers a different             │
│ [J]Triggers     │  area of the screen. Read [L]Install first, set the keys             │
│ [K]Config file  │  in the [E]config file, then see [VS]Troubleshooting.                │
│[VA]Changelog    │                                                                      │
│                 │  Search the docs                                                     │
│                 │                                         ┌────────────┐               │
│                 │ [R]_________________________________  [T]   Search   │               │
│                 │                                         └────────────┘               │
│                 │                                                                      │
│                 │ [ZA]Privacy  [ZS]License  [ZD]Source  [ZF]Issues                     │
│                 │                                                                      │
└─────────────────┴──────────────────────────────────────────────────────────────────────┘
```

ツールバーの拡大(跨ぎと内側寄せ):

```
   ┌──────────┐
 [FA]    ·    │
   └──────────┘
  ^ hint center = element left edge; left half outside, right half over
```

```
  ┌──────────┐┌──────────┐
[FA]    ·    ││ [FS]  ·  │
  └──────────┘└──────────┘
                ^ hint left edge = element left edge + 2pt (pushed inside)
```

注記

- 1 文字ヒント 12 個は「押されやすい」対象に出ている: タブ 3、サイドバー 4、本文のリンク 2、
  検索入力欄、`Search` ボタン、新規タブ。残りは 2 文字ヒント 13 個
- **1 文字に使った文字は 2 文字ヒントの 1 文字目に使わない**。この図では 1 文字が
  `A S D G H J K L E R T U`、2 文字の 1 文字目が `F W V Z` で、集合が重なっていない
- どの対象を 1 文字にするかの規則は未決(`../open-questions.md`「1 文字ラベルを配る優先順位の規則」)。
  この図の割り当ては例示であって、実装の入力にはならない
- 跨ぎ: `[L]Install` のようにヒントと語のあいだに空白がない箇所はすべて左辺跨ぎ。
  入力欄とボタンでは、ヒントの右端が枠線の列に重なる形で描いてある
- ツールバーは密で、隣のアイコンのヒントと衝突する。拡大図 B のとおり、衝突する側は
  自分の要素の内側へ右にずれる(`design-system.md`「配置規則」)。図の 6 個のうち、
  左端の 1 個は窓の左端に寄っているため、同じく内側寄せになる
- タイトルバーの信号機ボタンも対象だが、図の可読性のため省いた
- モードのチップは出ない。左クリック入口は既定の入口で、「いつもと違う」ことがない

- この状態でも Esc と trigger の再押下は取り消しとして効く

登場フロー: F5 の 2 手目。

│  Docs           │                                                                      │

注記

- ヒントは抜き(白い面 + 縁)。W1 と対象も文字も同じで、**塗り/抜きだけが違う**。
  1 文字と 2 文字の区別は幅と文字数にも載っているので、色だけに意味を置いていない
- mode chip `⟨ Right click ⟩` はコンテンツ領域の上端中央、タイトルバーの下に浮く。
  図ではツールバーの上に 1 行を割いてあるが、実際はツールバーに重なる
- チップは**入口が開いているあいだずっと出たまま**。1.2 秒で消える notice chip とは違う
- 打つキーの扱いは W1 と同じ。絞り込み後の見え方も W2 と同じ(抜きのまま薄くなる)

### W4a メニューバー左(アプリのメニュー)

登場フロー: F6 の 2 手目。
この画面の役割: メニュータイトルを隠さずに、真下へヒントを吊るす。

```
┌────────────────────────────────────────────────────────────────────────────────────────┐
│  Apple    Safari    File    Edit    View    Window    Help                             │
└────────────────────────────────────────────────────────────────────────────────────────┘
    [A]      [S]      [D]     [G]     [H]      [J]      [K]
```

注記

- ヒントはバーの**下辺の外側**に吊るす。バーの項目(タイトル・アイコン)には決して重ねない
- 中心 x は各メニュータイトルの中心に合わせる。左辺跨ぎはウィンドウ入口だけの規則で、ここでは使わない
- 項目数はたいてい 10 未満なので 1 文字ヒントで足りる。2 文字が出るのは例外
- チップは出ない。メニューバーに出ていること自体が入口の区別になる
- メニューを開いたあとは macOS 標準のキー操作に任せる。開いたメニューにヒントは出し直さない
  (`../decisions.md`「メニューやアイコンを押して開いたあとは…」)

### W4b メニューバー右(ステータスアイコン)

登場フロー: F6 の 2 手目(別の trigger)。
この画面の役割: 区別しづらいアイコン列に、1 文字ヒントを 1 対 1 で吊るす。

```
┌────────────────────────────────────────────────────────────────────────────────────────┐
│  ...                 [·]  [·]  [·]  [·]  [·]  [·]  Control Center   Sat 21 Sep  9:41   │
└────────────────────────────────────────────────────────────────────────────────────────┘
                       [A]  [S]  [D]  [G]  [H]  [J]       [K]               [L]
```

注記

- 左端の `...` は W4a が描いている範囲。1 回の入口で扱うのは右側だけ
- ステータスアイコン、Control Center、時計はすべて対象。アイコンの絵柄はヒントに隠されない
- 幅の狭いアイコンが並ぶので、中心合わせのままヒントがアイコンからはみ出す。これは許す
- チップは出ない

### W5 ステータスメニュー

登場フロー: F7 / F8 / F9。
この画面の役割: 常駐の状態を見せ、設定ファイル・無効化・状態ウィンドウ・終了への入口を出す。

├────────────────────────────────┤

├────────────────────────────────┤

設定エラー

```
menu bar icon: tag outline + "!" (bottom right)
┌────────────────────────────────┐
│  Config error — see Status…    │
├────────────────────────────────┤
│  Open Config File              │
│  Reload Config                 │
├────────────────────────────────┤
│  ✓ Disable in Slack            │
├────────────────────────────────┤
│  Status…                       │
├────────────────────────────────┤
│  Quit Hintjump            ⌘Q   │

```

注記

- 項目と並び、区切りの位置は 3 状態で共通。**先頭に 1 行と区切りが増えるだけ**
- `Update to 1.2.0…` と `Config error — see Status…` は同時には出ない(エラーが優先)。
  アイコンの点と `!` も同様に排他
- `✓ Disable in Slack` のチェックは、そのアプリで無効化中であることを示す。
  アプリ名は手前のアプリの名前が入る(図は Slack を例にした)
- キー等価を出すのは `Quit Hintjump` だけ。4 つの trigger はグローバルショートカットなので
  メニューには出さず、状態ウィンドウの Triggers 節に出す
- アイコンは単色のテンプレート画像で、メニューバーの外観に追従する。中のグリフは未決
  (18pt で判別できることが条件)

- 独自の色・独自のクロームは持たない。システム外観とシステム部品だけで組む
  (`design-system.md`「状態ウィンドウの部品」)

  `1.2.0 available`。メニュー項目を押すと状態ウィンドウが開いて About 節に着く
- `What's New` は開閉。開くと変更履歴が出る。履歴はアプリ内に持つので通信しない
- 未決: 更新の仕組み(`../handoff.md`「更新を知らせる仕組み」)。Homebrew だけに任せる形に
  決まったら、`Update…` ボタンは無くなり、代わりに `brew upgrade hintjump` を出す 1 行になる
- どちらの形でも解析通信はしない。通信するのは更新の確認だけ

注記

- notice chip は 1.2 秒だけ出て消える。位置は mode chip と同じ(コンテンツ領域の上端中央)
- チップが出ているあいだにキーを押しても何も起きない。ヒントは 1 つも出ていない
- 無効化中のアプリではヒント計算そのものを行わない。チップだけが出る
- チップにオレンジは使わない。オレンジは 1 文字ヒント専用
- 図中の `note:` 行は説明であって UI 文言ではない

**権限が外れた**

trigger を押した時点で Accessibility の権限が無いと、チップではなく**状態ウィンドウが開く**
(W6 の初回起動の状態と同じ見た目)。初回起動との違いは開くきっかけだけで、
初回起動は**起動時**に自動で開き、権限喪失は**trigger を押したとき**に開く。
チップで済ませないのは、その場でできることが何も無く、行き先を出す必要があるため。

**IME がオンのまま**

何も特別なことは起きない。ヒントは普通に出る。日本語入力のまま打ったキーは文字集合に
一致しないので無視され(飲み込まれ)、画面は変わらない。Esc で閉じる。専用の案内も
チップも出さない(`../decisions.md` の 2026-09-21 の決定)。ワイヤーは無い。

## 2. フロー

### F1 初回起動

1. Homebrew で入れて起動する → メニューバーにステータスアイコンが出る
2. 権限が無いことを検知 → 状態ウィンドウが自動で開く(W6 初回起動)
3. `Open System Settings…` を押す → システム設定のアクセシビリティの一覧が開く
4. 一覧で Hintjump を入れる → アプリが付与を検知し、状態行が `(v) Granted` に変わる
5. ウィンドウはそのまま。利用者が閉じる → 常駐だけが残る
6. Triggers 節で 4 つのキーを見る → 変えたければ `Open` で設定ファイルを開き `Reload`
7. 最初の trigger を押す → 300ms 以内にヒントが出る(F2 へ)

```
[install] -> [launch] -> [Not granted] -> [grant] -> [Granted] -> [trigger] -> [hints]
  分岐(付与せずに閉じる): 常駐は続き、次の起動で状態ウィンドウがまた自動で開く
```

### F2 通常利用(1 文字)

1. trigger(左クリック入口)を押す → 以後キーはアプリに届かない
2. 手前のウィンドウの target を読む → **300ms 以内**に全ヒントを一度に出す(フェードなし、W1)
3. 目的の要素の 1 文字ヒント `[R]` の `r` を打つ → 一致
4. その要素が左クリックされる → 同時に全ヒントが消える(フェードなし)
5. 何も残らない。次の操作は普通のキーボード操作に戻る

分岐: 対象が 0 件なら 2 で notice chip `Nothing to click here` が 1.2 秒出て終わる(W8)。
分岐: 文字集合にないキーは無視され、画面は変わらない。Esc で取り消して閉じる。

```
[trigger] -> [read targets] -> [hints] -> [1 char] -> [click] -> [end]
  [trigger] から [hints] までが 300ms 以内
  分岐(対象 0 件): [trigger] -> [notice chip 1.2s] -> [end]
  分岐(取り消し): [hints] -> Esc / 同じ trigger / マウス / アプリ切替 -> [end]
```

### F3 通常利用(2 文字)

1. trigger を押す → 300ms 以内に全ヒント(W1)
2. 目的の要素が 2 文字ヒント `FJ` → `f` を打つ
3. `F` で始まらないヒントが全部消える → 残った 6 個は打った字が薄くなる(W2)
4. `j` を打つ → 一致
5. その要素が左クリックされる → 残っていたヒントも消える

分岐: 3 の状態で Backspace → 絞り込み前に戻り、全ヒントが復帰する(W1)。何度でも戻せる。
分岐: 3 の状態で 2 文字目が一致しないキー → 無視。画面は変わらない。

```
[trigger] -> [hints] -> [1st char] -> [narrowed] -> [2nd char] -> [click] -> [end]
  分岐(Backspace): [narrowed] -> [hints] に戻る(全ヒントが復帰。何度でも戻せる)
  分岐(取り消し): [narrowed] -> Esc / 同じ trigger -> [end]
```

### F4 取り消し

1. ヒントが出ている(W1 / W2 / W3 のいずれか)
2. Esc を押す → ヒントが消える。何も押されない
3. 同じ trigger をもう一度押す → 同じく消える
4. 別の trigger を押す → いまのヒントを閉じ、その入口で出し直す
5. マウスでクリックする → ヒントを閉じ、**そのクリックはアプリに通す**
6. アプリを切り替える / 対象のウィンドウが消える → ヒントを閉じる

```
[hints] -> [cancel] -> [end]
  Esc / 同じ trigger の再押下 -> 閉じる。何も押されない
  別の trigger -> 閉じて、その入口で出し直す
  マウスクリック -> 閉じる。そのクリックはアプリに通す
  アプリ切替 / 対象ウィンドウの消失 -> 閉じる
```

### F5 右クリック入口

1. 右クリックの trigger を押す → キーはアプリに届かない
2. 300ms 以内に抜きヒントが出て、上端中央に mode chip `Right click` が出る(W3)
3. チップは入口が開いているあいだ出たまま
4. 目的のヒントを打つ(1 文字ならそのまま、2 文字なら絞り込んでから 2 文字目)
5. その要素が**右クリック**される → ヒントとチップが同時に消える
6. コンテキストメニューが開く
7. 以後は macOS 標準のキー操作(矢印、頭文字、Enter)

```
[trigger(right)] -> [outlined hints + chip] -> [char] -> [right click] -> [menu opens]
  -> 以後は macOS 標準のキー操作(矢印、頭文字、Enter)。Hintjump は関与しない
  分岐(取り消し): Esc / 同じ trigger -> [end](ヒントとチップが同時に消える)
```

### F6 メニューバー入口

1. メニューバー左(または右)の trigger を押す
2. 300ms 以内にバーの直下へ 1 文字ヒントが吊るされる(W4a / W4b)。チップは出ない
3. 目的のヒントを打つ → 一致
4. そのメニュータイトル(またはステータスアイコン)が左クリックされ、ヒントが消える
5. メニュー / パネルが開く
6. 以後は macOS 標準のキー操作(矢印、頭文字、Enter)

開いたメニューの中を打ちたい場合も、ヒントは出し直さない。
開いたパネルの中をヒントで押したいときは、ウィンドウ入口を押し直す(独立した 2 回の操作)。

```
[trigger(bar)] -> [hints under the bar] -> [1 char] -> [click] -> [menu opens]
  -> 以後は macOS 標準のキー操作(矢印、頭文字、Enter)。開いたものにヒントは出し直さない
  分岐(取り消し): Esc / 同じ trigger -> [end]
```

### F7 設定ファイル

1. ステータスメニューの `Open Config File` を押す → 既定のエディタで開く
2. 編集して保存する → アプリはまだ古い設定で動いている
3. `Reload Config` を押す → 読み直す
4. 成功 → 状態ウィンドウの Config 節が `Loaded at 12:03` に更新される
5. 失敗 → アイコンの右下に `!`、メニュー先頭に `Config error — see Status…`
6. その項目を押す → 状態ウィンドウが開き、Config 節に赤行 ``Line 12: unknown key `hotkey_left` ``
7. 直して `Reload` → 赤行とアイコンの `!` が消える

未決: 保存を監視して自動で読み直すかどうか(初版は `Reload Config` だけの想定)。

```
[Open Config File] -> [edit] -> [Reload Config] -> [Loaded at hh:mm]
  分岐(エラー): [Reload Config] -> [icon "!" + menu 行 + 赤行] -> [直す] -> [Reload Config]
```

### F8 更新

1. 更新があることを検知 → アイコンの右下に点が出る(W5 更新あり)
2. メニューを開く → 先頭に `Update to 1.2.0…`
3. 押す → 状態ウィンドウが開き、About 節に着く(W7)
4. `1.2.0 available` の隣の `Update…` を押す → 更新が始まる
5. `What's New` を開く → 何が変わったかをその場で読む
6. 更新が終わる → 点が消える

未決: 更新の仕組み。Homebrew だけに任せる形に決まったら、4 は `Update…` ボタンではなく
`brew upgrade hintjump` を表示する 1 行になり、実行は利用者が Terminal で行う(W7 の下の図)。

```
[update found] -> [dot on icon] -> [menu row] -> [About section] -> [Update…] -> [dot gone]
  [What's New] を開くと変更履歴が読める(通信しない)
  分岐(未決: Homebrew だけ): [About section] -> [brew upgrade hintjump を表示] -> 利用者が実行
```

### F9 アプリで無効化

1. 無効にしたいアプリを手前にする → メニュー項目が `Disable in Slack` になる
2. ステータスメニューを開いて押す → 設定ファイルの除外リストに書かれる
3. メニューを開き直す → `✓ Disable in Slack` にチェックが付く
4. そのアプリで trigger を押す → ヒントは出ず、notice chip `Off in Slack` が 1.2 秒出る(W8)
5. 戻すときは同じ項目をもう一度押す → チェックが外れ、次の trigger からヒントが出る

```
[Disable in <App>] -> [write to config] -> [checked] -> [trigger there] -> [notice chip 1.2s]
  分岐(解除): 同じ項目をもう一度押す -> チェックが外れ、次の trigger からヒントが出る
```

## 3. 横断仕様

### 3.1 タイミング表

| 対象 | 値 | 備考 |
|---|---|---|
| trigger のキーダウン → ヒント可視 | 300ms 以内 | 予算。超えたら遅いと感じられる |
| ヒントの表示 | 0ms(フェードなし) | 計算が終わった瞬間に全部を一度に出す。描画は 1 フレーム |
| ヒントの消滅 | 0ms(フェードなし) | クリック時・取り消し時とも同じ |
| 絞り込み(1 文字目を打った後の再描画) | 0ms(フェードなし) | 不一致は即座に消える |
| mode chip | 入口が開いているあいだ常時 | 消えるのは入口が閉じるとき |
| notice chip | 1.2 秒で自動的に消える | 出ているあいだキー入力は何も起こさない |

動きはどこにも無い。したがって prefers-reduced-motion への配慮は自明に満たす。
ホバー状態も無い(オーバーレイはポインタを受けない)。
