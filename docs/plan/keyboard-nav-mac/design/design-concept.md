# Hintjump デザインコンセプト

作成: 2026-09-21。この文書は「何をどう決めたか、なぜか」を残す。そのまま使える値は `design-system.md`、
画面ごとのワイヤーとフローは `wireframes.md` にある。製品としての決定(入口 4 つ、動作、英数字、設定
ファイル、通信方針)は `../decisions.md` と `../handoff.md` にあり、ここでは繰り返さない。

## 概要

| 項目 | 内容 |
|---|---|
| プロダクト名 | Hintjump |
| 一言でいうと | trigger を押すと押せる要素に英数字の hint が出て、打つとそこが押される macOS 常駐アプリ |
| 主な利用状況 | キーボードに手を置いたまま作業していて、画面の 1 か所を押すためだけにポインタへ手を移したくない瞬間。1 回あたり 1 秒未満、1 日に何十回も起きる |
| 利用文脈 | macOS デスクトップ。他のアプリの画面の上に一瞬だけ重なる。利用者は手元を見ず、画面のヒントだけを見て打つ |
| プラットフォーム | macOS 常駐(メニューバー)。UI は英語 |
| デザイン基盤 | macOS ネイティブ: SwiftUI / AppKit、SF 書体、SF Symbols、状態ウィンドウはシステムカラー。ヒントのオーバーレイだけは固定の独自パレット |
| 基盤を選んだ理由 | 設定面はシステムに任せると作る量と学習コストがゼロに近い。一方オーバーレイは他アプリの画面に重なるので、システムの外観に従うと背景次第で読めなくなる |

## テーマ方針

ライト / ダークで扱いを分けるのはオーバーレイと設定面の 2 つに分かれる。

- ヒントとチップ: 固定パレット。OS の外観に追従しない。理由: 重なる相手は他アプリの画面で、同じ瞬間に
  ライトの領域とダークの領域が混在する。追従させると背景次第でコントラストが崩れる
- 状態ウィンドウとステータスメニュー: OS の外観に追従する。独自色もテーマ切替も持たない
- 利用者によるテーマ選択は持たない(`../decisions.md`: テーマは作らない)
- Increase Contrast: ヒントは既に文字 4.5:1 以上を満たすため、値を変えない
- Reduce Transparency: 抜きヒントの面を白 92% から白 100% にする

## デザイン原則

4 つ。これ以上足さない。

### 1. 0.3 秒で読める > 馴染む

ヒントの配色は固定で、OS の外観にも背後のアプリにも追従しない。フラット、アニメーションなし。

- 効く判断: 「システム素材(半透明・システムアクセント)にすれば macOS らしくなる」という案が出たときに採らない
- 捨てるもの: macOS らしい溶け込み。ヒントは意図的に浮かせる

### 2. 1 文字が主役

オレンジは 1 文字ヒントだけに使う。2 文字ヒントは暗い無彩色。1 文字目を打った瞬間、一致しないヒントは
1 文字ヒントも含めて全部消える。

- 効く判断: 新しく色が必要になったとき、オレンジを転用せず「色を足さない」側を選ぶ(更新の点、エラー、
  チップ、状態ウィンドウはすべて無彩色かシステムカラー)
- 捨てるもの: 全ヒントを同じ扱いにする一貫性

### 3. 出したら黙る

常時の説明パネルもモード表示も持たない。チップが出るのは「いつもと違う」(右クリック入口)か「何も
できない」(対象 0 件・無効化中)ときだけ。

- 効く判断: 初見の分かりにくさを UI の追加で埋めない。埋めるのは README と最初の 1 回の権限案内
- 捨てるもの: 初見への手取り足取り

### 4. 設定面は macOS に任せる

状態ウィンドウとメニューは、システム外観・システム部品・システムカラーだけで作る。独自色も独自クロームも
持たない。

- 効く判断: 状態ウィンドウにブランドの色やロゴを置きたくなったときに置かない
- 捨てるもの: 設定面でのブランドの主張。主張はヒントで足りている

## ブランド軸

| 軸 | 位置(1–5) | UI での現れ方 |
|---|---|---|
| 静か ⇔ にぎやか | 2 | 有彩色は 1 色、動きゼロ、同時に出るのはヒントだけ |
| 硬質 ⇔ やわらかい | 1 | 角丸 4pt、等幅フォント、1pt の縁で背景から切る |
| 端正 ⇔ 手作り感 | 1 | 配置規則が一意に決まる、イラストなし |
| 情報密度 高 ⇔ 低 | 2(ヒント) / 3(状態ウィンドウ) | ヒントは最小面積、状態ウィンドウはシステム標準の密度 |
| 実直 ⇔ 遊び心 | 1 | 文言は動詞始まりの命令形、感嘆符なし |

「にぎやか」側に振らなかったのは、ヒントが他アプリの画面に重なる部品で、装飾がそのまま作業の邪魔に
なるため。「やわらかい」側に振らなかったのは、大きな角丸と淡い面が明るい背景で沈むため。

## 参照にしたものと採用・不採用

Refero での調査は 2026-09-21。

| 参照 | 見たもの | 採用したこと | 採用しなかったこと | 理由 |
|---|---|---|---|---|
| Cron Calendar (cron.com) | 全体の配色と面の作り | 近黒の面に白文字、鮮やかなオレンジを 1 色だけ主要な操作に使う。フラット、小さい角丸、影なし。計器盤の直截さ | — | 有彩色 1 色という制約がそのまま「1 文字だけ色を持つ」規則になる |
| PlanetScale (planetscale.com) | 技術的モノクロ + 少数の機能色 | ヒント文字を等幅で組む精密さ、鋭い境界線 | 全体の配色構成 | 借りるのは組み方だけ。配色の土台は Cron に一本化する |
| Raycast / Relume / Jace の kbd 表現 | 押すキーをそのまま見せる読み方 | 「打つ文字を字形のまま出す」という読ませ方 | キーシャドウ、ピル形状のキーキャップ | 淡い面が明るい背景で埋もれ、縁取りで補う分タグが大きくなる |
| Homerow | 公式サイトのデモ | — | 淡いクリーム黄のタグ、吹き出しの尾、要素の上に浮く配置、画面右下に常時出る暗い説明パネル、黒い角丸正方形のアプリアイコン、テーマ名 3 種、独自の用語 | `../decisions.md` の「先行作をなぞらない」。用語の置き換えは下のボイス&トーンの表にある |
| Vimium 系 | 黄色いタグ | — | 黄色のタグ | ジャンルの見慣れた見た目そのもので、別物として出す条件に合わない |
| 却下した方向: キーキャップ | — | — | 全部 | 淡い面が明るい背景で埋もれる |
| 却下した方向: システム素材 | — | — | 全部 | 半透明で背景次第にコントラストが揺れ、0.3 秒で読む要件と相性が悪い |

### 参照ロック

- 一次参照は Cron ひとつ。方向性で迷ったら Cron 側に寄せる
- Cron から保持する形質: 有彩色は 1 色だけ / フラットで高コントラスト / 小さい角丸 / 影や光彩で飾らない
- 二次参照から借りるのは細部だけ: PlanetScale からは等幅と鋭い境界線、kbd 表現からは読ませ方
- 役割規則: オレンジは 1 文字ヒント(塗り・抜き・打った後の薄い字)にだけ使う。更新の点、設定エラー、
  チップ、状態ウィンドウにはオレンジを使わない
- 平均しない: 「明るい面 + 淡いアクセント」に丸めない。Cron の鋭さを保つ

## ボイス&トーン

- 英語 UI。センテンスケース(メニュー項目だけは macOS 慣例のタイトルケース)。動詞始まり。感嘆符なし。
  "please" を使わない。1 文は 12 語以内を目安
- 日本語の文書側(この design/ 配下)は常体で書き、UI 文言は英語のまま引用する

### 用語

| 使う | 使わない | 対象 |
|---|---|---|
| hint | label / dynamic shortcut / tag(UI 文言では) | 要素に出る英数字のタグ |
| trigger | hotkey / activation shortcut | 4 つのショートカット |
| target | element / item | 押せる要素 |
| Disable in \<App\> / disabled apps | exceptions / exclusions / blocklist | アプリ単位の除外 |
| config file | settings / preferences | テキスト設定 |
| Status | Settings / Preferences | 状態ウィンドウ |

### なぞらない文言

先行作のサイトとアプリで使われている次の文は、そのままも言い換えも使わない。UI 文言、README、配布
ページのいずれでも避ける。

- "Keyboard shortcuts for your entire Mac"
- "Click anywhere, without a mouse"
- "Navigate buttons, links, and UI elements instantly with keyboard labels"
- "Works with your favourite apps"
- "Loved by keyboard enthusiasts"
- "Type the letters shown to click that element"
- "Chain clicks"
- "Manipulate macOS masterfully, minus the mouse"
- "The universal command palette for your Mac"

確定した UI 文言の一覧は `wireframes.md` の文言表にある。

## 非スコープ(デザインとして意図的に持たないもの)

| 持たないもの | 理由 | 代わりに満たす手段 |
|---|---|---|
| テーマ(Dark / Light / 配色の選択) | オーバーレイは背景が混在するので固定値のほうが確実に読める。設定面は OS の外観で足りる | 固定パレット + OS 外観への追従(テーマ方針) |
| 常時の説明パネル | 視線はヒントにあり、画面の隅のパネルは読まれない。先行作の見た目に最も近づく部分でもある | 最初の 1 回だけの権限案内と README |
| アニメーション、フェード、トランジション | 300ms の予算のうち動きに使える時間がない。動きは待ち時間として体感される | 一度に全部出す / 一度に全部消す |
| ホバー状態、ツールチップ | オーバーレイはポインタを受けない非アクティブ化パネル。ホバーに情報を載せると誰にも届かない | 情報はヒントの形と文字数に載せる |
| 状態ウィンドウの独自クローム(独自の背景色、ロゴ、カスタムコントロール) | システム部品なら外観追従・拡大・支援技術が自動で付いてくる | システム部品とシステムカラーのみ |
| 通知バナー | 通知権限がもう 1 つ増え、作業中に割り込む | ステータスアイコンの点 + メニュー項目 + 状態ウィンドウ |
| オレンジを 1 文字ヒント以外に使うこと | 色の役割が 1 つでも増えると、1 文字を色で拾う判断が鈍る | 更新・エラー・チップは無彩色かシステムカラー |
| ヒントの見た目の設定項目 | 初版は固定値で出し、実利用で不足が分かってから足す | 未決: ヒントの大きさを設定ファイルで変えられるようにするか(`../open-questions.md`) |

## 決定ログ

すべて 2026-09-21。原典と詳しい理由は `../decisions.md`。

| ラウンド | 決定したこと | 却下した選択肢 | 理由 |
|---|---|---|---|
| 1 | デザインの成果物は `design/` 配下に複数ファイルで置き、ワイヤーはオーバーレイ 4 状態 + 常駐メニュー + 権限案内 + 更新 + 端の状態の全部を対象にする | オーバーレイ + 常駐メニュー + 権限案内のみ / オーバーレイ 4 状態のみ | 設定の入口と端の文言を後で決め直すことになる |
| 1 | ヒントは「標識」方向。不透明の近黒タグに白文字、1 文字だけ鮮やかなアクセントで塗る。小さい角丸、尾なし、1pt の縁で背景から切る | キーキャップ(キーシャドウ / kbd ピル) / システム素材(半透明 + システムアクセント) | 前者は淡い面が明るい背景で埋もれる。後者は背景次第でコントラストが揺れ 0.3 秒の要件に合わない |
| 1 | 1 文字の役割色は赤みのオレンジ | エレクトリックブルー / 緑 / 無彩色のみ | 青は macOS の選択・リンク色と混ざる。緑は先行作のフォーカス色と成功色に衝突する。無彩色のみは暗いアプリで白タグが目立ちすぎ、明るいアプリで逆転が起きる |
| 1 | 右クリック入口は「塗り / 抜きの反転 + 上端中央のモードチップ」で見分ける | モードチップだけ / ヒントの色を丸ごと変える / 見分けなし | チップだけでは視線がヒントにあるとき見えない。色を変えると 1 文字の役割色と意味が衝突する。見分けなしでは押し間違いに気づけない |
| 2 | ヒントの中心を要素の左辺に、垂直中央に合わせる。左へはみ出せない場所では要素の内側左端に寄せる | 左上角に重ねる / 中央に重ねる | 左上角はテキストの先頭と小さいアイコンを隠し、ジャンルの見慣れた見た目になる。中央は小さい要素を丸ごと隠す |
| 2 | 1 文字目を打ったら不一致ヒント(1 文字ヒントを含む)は即消す。一致ヒントはその場に残し、打った字を薄くし、幅は変えない | 不一致を薄く残す / 一致ヒントを 2 文字目だけに縮める | 前者は画面が騒がしいまま。後者はタグが跳ねて見え、何を打ったかの手がかりが消える |
| 2 | 設定の面はステータスメニュー + 小さな状態ウィンドウ 1 枚。ウィンドウは初回起動の権限案内と兼用 | メニューだけ / 標準の設定ウィンドウ(⌘,)をタブで / 両方 | メニューだけでは初回の権限案内に気づけず、設定エラーの行を見せる場所がない。標準の設定ウィンドウは設定ファイルとの二重管理になり、先行作の設定画面に形が近づく。両方は同じことを 2 回言う |
| 2 | 更新はステータスアイコンの小さな点 + メニュー先頭の項目 + 状態ウィンドウの About 節で知らせる | macOS の通知バナー / 両方 | 通知権限がもう 1 つ増え、作業中に割り込む。両方は同じことを 2 回言う |
| 3 | 日本語入力がオンのまま trigger を押しても、何も特別なことをしない。ヒントは普通に出て、合わないキーは無視され、Esc で閉じる | trigger 時に入力ソースを読み、ABC 系でなければ案内の帯を出す | 分かりやすいが、入力ソース判定のコードを持つことになる。同日の「入力ソースに依存しない」決定と整合させた |
