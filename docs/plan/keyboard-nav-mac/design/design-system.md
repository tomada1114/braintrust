# Hintjump デザインシステム

作成: 2026-09-21。読み手は UI を実装する別のセッション。ここにはそのまま使える値だけを置く。
なぜその値かは `design-concept.md`、画面ごとの配置とフローは `wireframes.md` にある。
製品としての決定は `../decisions.md` / `../handoff.md`、未決の一覧は `../open-questions.md`。

寸法の単位はすべて pt(macOS のポイント)。

## 1. コンポーネントインベントリ

この表に無い部品を作らない。必要になったら表に足してから作る。

| コンポーネント | 由来 | バリアント | 状態 |

| status icon | `NSStatusItem` のテンプレート画像 | 通常 / 更新あり / 設定エラー | 更新ありとエラーは同時に出さない(エラー優先) |

| — config row | システム部品(等幅の選択可テキスト + プッシュボタン 2 つ + 状態行) | — | 読み込み OK / 読み込みエラー |
| — triggers list | システム部品(読み取り専用の 4 行リスト) | — | 単一。値は設定ファイル由来 |

システムコントロールに同等品がない。それ以外はすべてシステム部品で作る。

## 2. ヒント

### 2.1 書体と寸法

| 項目 | 値 |
|---|---|
| 書体 | システムの等幅(`NSFont.monospacedSystemFont`)の Semibold |
| サイズ | 13pt |
| 字形 | 大文字で表示する(打つのは小文字でもよい) |
| 高さ | 20pt |
| 左右パディング | 5pt |
| 最小幅 | 20pt(1 文字はほぼ正方形) |
| 2 文字の幅 | 約 26pt |
| 角丸 | 4pt |
| 縁の太さ | 塗りバリアント 1pt / 抜きバリアント 2pt |
| 影・グラデーション・吹き出しの尾 | なし。線と面はすべてフラット |

### 2.2 バリアント

| 名前 | 用途 | 面 | 文字 | 縁 |
|---|---|---|---|---|
| `hint/one` | 1 文字、左クリック入口 | `#FF4700` | `#111111` | 1pt 白 60%(暗い背景から切るハロー) |
| `hint/two` | 2 文字、左クリック入口 | `#1D1D1F` | `#FFFFFF` | 1pt 白 60% |
| `hint/one-outline` | 1 文字、右クリック入口 | 白 92%(Reduce Transparency 時は 100%) | `#BF3300` | 2pt `#FF4700` |
| `hint/two-outline` | 2 文字、右クリック入口 | 白 92%(同上) | `#1D1D1F` | 2pt `#1D1D1F` |

メニューバー入口(左・右)は 1 文字ヒントがほぼ確実に配れる。見た目は `hint/one` と同じ(左クリック扱い)。

### 2.3 打った字

2 文字ヒントの 1 文字目を打ったときだけ、打った字を薄くする。残り 1 文字はそのまま。タグの幅は変えない。

| 対象 | 打った字の色 |
|---|---|
| `hint/two` | `#8A8A8E` |
| `hint/two-outline` | `#6E6E73` |

### 2.4 色だけに意味を載せない

- 1 文字と 2 文字は、色に加えて幅と文字数でも違う
- 左クリック入口と右クリック入口は、色に加えて塗り / 抜きでも違う。右クリック入口ではさらに mode chip が出る
- 打った字は、薄さに加えて「残り 1 文字だけが濃い」という位置関係でも分かる

## 3. 配置規則

上から順に適用する。

1. 基準: ヒントの中心 x を要素の左辺(minX)に、中心 y を要素の中央(midY)に合わせる。結果として
   ヒントの左半分は要素の外、右半分は要素に重なる
2. 要素が 20pt より小さくても中心合わせのままにする(ヒントが要素からはみ出してよい)
3. 左にはみ出せないとき — ヒントの左辺がウィンドウまたは画面の左端から 2pt 未満になるとき — は、
   ヒントの左辺を要素の左辺 + 2pt に寄せる(要素の内側に押し込む)
4. 衝突の解消は、要素を上 → 下、左 → 右の順に処理する。先に置いたヒントと重なる場合:
   1. 自分の要素の内側で右へずらす(上限は 要素の右辺 − ヒントの幅)
   2. それでも重なるなら 4pt 下へずらす
   3. それでも重なるなら重なりを許す(稀)
5. メニューバー入口では、ヒントをバーの直下に吊るす。ヒントの上辺 = メニューバーの下辺 + 2pt、
   中心 x = 各メニュー項目 / ステータス項目の中心。バーの項目(タイトル・アイコン)は隠さない
6. 最後に画面矩形へクランプする。ヒントは画面外に出ない

```
基準(左辺に跨ぐ)

        ┌──────────────────────┐
        │                      │
   ┌────┼────┐                 │      ヒントの中心 x = 要素の minX
   │ [A]│    │  Button         │      ヒントの中心 y = 要素の midY
   └────┼────┘                 │      左半分は外、右半分は重なる
        │                      │
        └──────────────────────┘
        ↑ 要素の左辺 (minX)

フォールバック(内側に押し込む)

  ║ ┌──────────────────────┐
  ║ │┌────┐                │           左端まで 2pt 未満のとき
  ║ ││[A] │  Button        │           ヒントの左辺 = 要素の左辺 + 2pt
  ║ │└────┘                │           中心合わせはやめる
  ║ └──────────────────────┘
  ║ └→ 2pt
  ↑ ウィンドウ / 画面の左端
```

## 4. タイミングと動き、キー処理

### 4.1 タイミングと動き

| 項目 | 値 |
|---|---|
| 表示 | 計算が終わった瞬間に全ヒントを一度に出す。フェードなし |
| 消去 | 一度に全部消す。フェードなし |
| 予算 | trigger のキーダウンからヒント可視まで 300ms 以内。描画自体は 1 フレーム |
| notice chip の表示時間 | 1.2 秒 |
| mode chip の表示時間 | 右クリック入口の間ずっと |
| アニメーション | なし。移動・拡大・回転・フェードのいずれも使わない |
| ホバー状態 | ない(オーバーレイはポインタを受けない) |

### 4.2 キー処理(オーバーレイ表示中)

オーバーレイ表示中、キーは背後のアプリに届かない。

| 入力 | 動作 |
|---|---|
| 文字集合内のキーが 1 文字ヒントに一致 | 即クリックして閉じる |
| 文字集合内のキーが 2 文字ヒントの 1 文字目に一致 | 絞り込む。不一致ヒント(1 文字ヒントを含む)を即消す。一致ヒントは打った字を薄くして残す |
| 2 文字目 | クリックして閉じる |
| Backspace | 1 文字戻す(絞り込み前の表示に戻る) |
| Esc | 取り消して閉じる |
| 同じ trigger の再押下 | 取り消して閉じる |
| 別の trigger | 閉じて、その入口で出し直す |
| 文字集合にないキー、修飾キー単体 | 無視する(飲み込む。何も表示しない)。日本語入力がオンのまま押した場合もこの扱いで、特別な表示はしない |
| マウスクリック | 取り消して閉じる。クリックは背後のアプリに通す |
| アプリ切替、対象ウィンドウの消失 | 取り消して閉じる |

## 5. チップ

| 項目 | 値 |
|---|---|
| 面 | `#1D1D1F` |
| 文字 | `#FFFFFF` |
| 書体 | SF Pro Text 12pt Medium |
| 高さ | 22pt |
| 左右パディング | 10pt |
| 角丸 | 11pt(ピル)。ピルはチップ専用で、ヒントは 4pt のまま |
| 縁・影 | なし |
| オレンジ | 使わない |
| 位置 | 対象ウィンドウのコンテンツ領域の上端中央、タイトルバー下 8pt |
| メニューバー入口 | チップを出さない(場所で入口が分かるため) |

- `mode` chip: 右クリック入口の間ずっと出る。文言 "Right click"
- `notice` chip: ヒントを出せないときに 1.2 秒だけ出て消える。表示中にキーを押しても何も起きない。
  文言は `wireframes.md` の文言表(対象 0 件 / 無効化中のアプリ)
- 権限が無い / 外れたときは、チップではなく状態ウィンドウを開く(他に取れる行動がないため)

## 6. ステータスアイコンとメニュー

### 6.1 アイコン

| 項目 | 値 |
|---|---|
| 形式 | テンプレート画像(単色。メニューバーの外観に追従する) |
| サイズ | 18×18pt |
| 図案 | ヒントタグの輪郭。角丸 4pt の矩形の線画。塗りつぶしにしない |
| 中のグリフ | 未決: 18pt で判別できるグリフ案を製品側で描き、オーナーが 1 つ選んだとき |
| 変種 | 通常 / 更新あり(右下に小さな点、単色) / 設定エラー(右下に小さな "!"、単色) |
| 変種の排他 | 点と "!" は同時に出さない(エラー優先) |
| 色 | 付けない。テンプレート画像なのでオレンジも使えない |

### 6.2 メニュー(`NSMenu`)

システム外観。キー等価を持つのは Quit だけ。

```
Update to 1.2.0…              ← 更新があるときだけ。押すと状態ウィンドウの About 節へ
Config error — see Status…    ← 設定エラーがあるときだけ。押すと状態ウィンドウの Config 節へ
──────────────────            ← 上の 2 項目のどちらかがあるときだけ
Open Config File
Reload Config
──────────────────
Disable in <App>              ← 手前のアプリ名。チェックで無効化中を示す
──────────────────
Status…
──────────────────
Quit Hintjump          ⌘Q
```

- `Update to 1.2.0…` と `Config error — see Status…` は同時に出さない(アイコンの変種と同じくエラー優先)。
  設定エラーが直った次のメニュー表示から更新項目が出る
- `Disable in <App>` を押すと、設定ファイルの除外リストに書く / 外す
- trigger の一覧はメニューに出さない。グローバルショートカットはメニューのキー等価として表示できないため、
  状態ウィンドウの Triggers 節に出す

## 7. 状態ウィンドウ

初回起動の権限案内と兼用する 1 枚。

| 項目 | 値 |
|---|---|
| タイトル | "Hintjump" |
| サイズ | 目安 460×560pt、リサイズ不可 |
| 外観 | システム外観(ライト / ダークに追従) |
| 部品 | システム部品のみ(SwiftUI `Form` / `GroupBox` 相当) |
| 余白・行間 | システム既定 |

### 節(上から)

| 節 | 内容 | 使うシステム部品 |
|---|---|---|
| 1. Accessibility | 状態行(付与済み: `checkmark.circle` + "Granted" / 未付与: `xmark.circle` + "Not granted")と `Open System Settings…` ボタン。未付与のときだけ理由を 1 文出す: "Hintjump reads on-screen controls and clicks them for you. macOS requires Accessibility access for that." | ラベル + SF Symbols + プッシュボタン |
| 2. Config | 設定ファイルのパス(等幅、選択可)、`Open` `Reload` ボタン、最終読み込み行。読み込み OK は "Loaded at 12:03"、エラーは `exclamationmark.triangle` + システムの赤文字で "Line 12: unknown key `hotkey_left`"(形式: `Line N: <理由>`) | 選択可テキスト + プッシュボタン 2 つ + ラベル + SF Symbols |
| 3. Triggers | 読み取り専用の 4 行: Click in window / Right-click in window / App menus / Status icons。各行の右にキー表記(⌘⇧Space など)。値は設定ファイル由来 | 読み取り専用のリスト / `LabeledContent` 相当 |
| 4. About | バージョン、`Check for Updates` ボタン、更新があるときは "1.2.0 available" と `Update…`、`What's New` の開閉で変更履歴(アプリ内に持つ) | ラベル + プッシュボタン + 開閉(disclosure) |

- Triggers の既定値 — 未決: 4 つの trigger の既定キーとヒント文字集合の既定値が決まったとき(`../open-questions.md`)
- `Check for Updates` の中身 — 未決: 更新を知らせる仕組み(Homebrew に任せる / アプリ内更新の仕組みを持つ)が決まったとき(`../open-questions.md`)

### 色と状態の示し方

- 色はシステムカラーのみ。独自色を持たない(§8 の 2 つ目の表)
- 状態は必ずアイコン + 文字で示す。色だけに載せない。理由: 強制配色や色覚特性で色差が失われると、
  Granted と Not granted の区別が消える

### 初回起動

- 権限が未付与なら、起動時に自動でこのウィンドウを開く
- 付与を検知したら状態行を Granted に変える。ウィンドウは開いたままにする(閉じるのは利用者)

## 9. アクセシビリティ

| 項目 | 基準 | 本プロダクトでの扱い |
|---|---|---|
| テキストコントラスト | 4.5:1 | ヒントの文字、打った字、チップの文字。実測は §10 |
| 非テキストコントラスト | 3:1 | ヒントの縁とハロー。実測は §10 |
| Increase Contrast | — | ヒントは既に 4.5:1 以上なので値を変えない |
| Reduce Transparency | — | 抜きヒントの面を白 92% から白 100% にする。ほかに半透明な部分はない |
| Reduce Motion | — | 動きが無いので自明に満たす。分岐を実装しない |
| キーボード操作 | 全機能に到達できる | オーバーレイは本質的にキーボードだけで完結する。状態ウィンドウとメニューはシステム部品なので既定で到達できる |
| 状態の示し方 | 色だけに載せない | ヒントは形と文字数、状態ウィンドウはアイコン + 文字で区別する |

### 制限: オーバーレイは VoiceOver の対象外

オーバーレイは非アクティブ化パネルで、フォーカスを受け取らない。したがって VoiceOver はヒントを読まない。
これは設計上の利点ではなく、割り切った制限として記録する。画面を見ずにこのアプリを使うことはできない。
状態ウィンドウとメニューはシステム部品なので、そちらは通常どおり読み上げられる。

## 10. コントラスト実測

`python3 scripts/check_contrast.py` の出力そのまま(2026-09-21 実行)。

```

----------------------------  -------  -------  ----  -----  --------  ------

打った字 (hint/two)               #8A8A8E  #1D1D1F  text  4.89   4.50      PASS

縁 orange on white             #FF4700  #FFFFFF  ui    3.41   3.00      PASS  
縁 orange on black             #FF4700  #000000  ui    6.15   3.00      PASS

白ハロー on black                 #FFFFFF  #000000  ui    21.00  3.00      PASS  
白60%近似 on black               #999999  #000000  ui    7.37   3.00      PASS  
面の分離 one/two 隣接               #FF4700  #1D1D1F  ui    4.93   3.00      PASS

チップ文字                         #FFFFFF  #1D1D1F  text  16.83  4.50      PASS
```

- 調整した値: 抜きヒントの 1 文字の文字色を `#C93700` から `#BF3300` に濃くした。白 92% の面が暗い背景に
  乗った近似(`#EBEBEB`)で 4.37 と 4.5:1 を下回ったため。§2.2 と §8.1 の値は調整後のものが入っている
- `面の分離 two on 暗いアプリ`(`#1D1D1F` on `#000000`、1.25)の FAIL は許容する。暗いアプリの上に置いた
  2 文字ヒントの面は背景とほとんど差が無いが、面の分離はこの組ではなく `hint/halo`(白 60% の 1pt 縁、
  黒の上で 7.37)が担っている。ヒントの輪郭はハローで見えるので、面どうしのコントラストは要件にしない
- `面の分離 one/two 隣接`(4.93)は、1 文字ヒントと 2 文字ヒントが隣り合ったときに面だけで区別できることの
  確認。3:1 を満たしている

## 11. 実装セッションへの指示

- オーバーレイ(ヒントとチップ)の色は §8.1 の固定値をそのまま使う。`NSColor` のシステムカラーや
  `controlAccentColor` を混ぜない。外観の変化にも追従させない
- ヒントの文字は `NSFont.monospacedSystemFont` の Semibold 13pt。フォント名を直書きしない
- 状態ウィンドウとステータスメニューは、システムコントロールとシステムカラー(§8.2)だけで作る。
  独自の背景色、独自のクローム、カスタム描画を足さない
- アニメーション API を使わない。`NSAnimationContext`、暗黙アニメーション、SwiftUI の `withAnimation`、
  フェードのいずれも入れない。表示と消去は 1 フレームで切り替える
- ヒントの文字集合と 4 つの trigger の既定値は設定ファイルから読む。コードに既定値を埋め込む前に
  `../open-questions.md` を見る(どちらも未決)
- ホバー状態、ツールチップ、マウス追従を足さない。オーバーレイはポインタを受け取らない
- ヒントの割り当てと配置計算(§2 の文字割り当て、§3 の配置規則、§4.2 の状態遷移)は Core に置く。
  Core は AppKit を import しない(`macos-app-template` の `docs/architecture.md`)。描画とパネル管理は
  UI / Platform 側に置く
- アクセシビリティの読み取りとクリックの合成は Platform 層のアダプタとして書き、Core のポートの
  向こう側に置く(同 `docs/architecture.md`。Platform はカバレッジの門の外なので、判断が要る処理は
  Core に移す)
