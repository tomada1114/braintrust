# keyboard-nav-mac

マウスに手を伸ばさず、画面上の押したい場所をキーボードで押すための macOS アプリ。ショートカットでラベルを出し、ラベルを打って押す、だけに機能を絞る。

## 誰の何の困りごとか

- 対象: マウスに手を伸ばさず、画面上の押したい場所をキーボードで押したい Mac ユーザー。最初の想定ユーザーはオーナー本人。利用者像は英語圏の開発者・キーボード派
- 困りごと: オーナーは Homerow を使っており、実際に使っているのは「自分で設定したショートカット(⌥F)でラベルを出し、文字を打って左クリックする」の 1 つだけ。Homerow の他の機能(スクロール、テキスト検索、連続クリック、Mission Control、効果音、テーマ、Hyperkey)は使っていない。スクロール機能は「できることが多すぎてよく分からない」ために使わなかった、とオーナー自身が述べている

## 実在する痛みか

観察されたこと — (1) オーナーが一番使う Claude Desktop(Electron 製)で Homerow がうまく動かない。同じ報告が Homerow の公開 issue #148 にあり 2024-12 から未解決(research/electron-ax-support.md)。(2) 画面全体に一気にラベルが出ると多くてきつい、というオーナーの実感。

想像にとどまること — 範囲ごとにショートカットを分けるとラベルが減って速くなる、という効果はまだ試していない。オーナー以外の需要は小さい可能性がある(この領域の過去最大の OSS が 3 年かけて到達した規模と、需要の票数の小ささは `docs/plan/author-fame-product/research/2026-09-mac-power-user-demand.md` の候補 1 を参照)。

主な動機には「Homerow のようなものを自分で実現してみたい」も含まれる。

## 既存プロダクトとの違い

- 既存: Homerow(有料・非 OSS、品質の基準)、Shortcat(非 OSS)、vimac と warpd(OSS、開発停止)、neru と mousemaster(OSS、活発)。ラベルを出して打つ方式そのものは Vimium 以来のジャンルで Homerow の発明ではない
- 差分: (a) 入口を分ける — 範囲と動作ごとに別のショートカットで呼び、1 回に出るラベルを減らし、入口ごとにできることを絞る。(b) 機能を「押す」ことだけに絞る。(c) OSS・無料。(d) 設定がテキストファイルで共有できる。(e) Claude Desktop や Slack などの Electron 系で動くこと(実機検証待ち。できない可能性がある)

看板は「できるだけ絞って 1 文字ラベルで押せる」こと。入口を分けて対象を減らし、アクティブウィンドウでは押されやすい要素に 1 文字を優先して配る(2026-09-21 決定)。メニューバーの入口は 1 文字が確実に成立する。

弱いところも明記する。ブラウザや Electron 系のウィンドウは要素が 26 個を大きく超えるのが普通で、1 文字になるのは一部にとどまる。どの要素を優先するかは推測で、外れた分は既存品と同じ 2 文字の体験になる。「覚えられるラベル(同じ要素に同じラベル)」を看板にする案は 2026-09-21 にオーナーが取り下げた。Electron 系で動くことは、Homerow が Slack で普通に動いたというオーナーの観察もあり、看板にはしない。(a)〜(d) だけでは Homerow の機能を減らした版に見える危険があり、neru が Electron の自動判別まで進めているので OSS の空席も狭まっている(research/electron-ax-support.md)。Homerow のクローンと見られないよう、見た目・用語・設定の構成・サイトの文言は独自にし、先行作への謝辞を書く。

## 何を作るか(現時点の像)

- 形態: macOS の常駐アプリ。アプリ名は Hintjump
- 中核の体験: ショートカットを押すと対象範囲の押せる要素に英数字のラベルが出て、ラベルを打つとその要素をクリックする。動作は左クリックと右クリックで、それぞれ別のショートカットから入る。ショートカットは全部で 4 個にする(アクティブウィンドウの左クリック、アクティブウィンドウの右クリック、メニューバー左のアプリメニュー、メニューバー右のステータスアイコン)。特定のアプリでは無効にできる。設定はテキストファイル
- AI の位置づけ: LLM は使わない。AX ツリーの取得、ラベルの割り当て、キー入力の状態遷移、クリックの合成で成立する

土台はオーナーの macos-app-template(`/Users/masuyama/ghq/github.com/tomada1114/macos-app-template`)。このテンプレートは App Sandbox が有効だが、他アプリの要素を読んでクリックを合成するにはサンドボックスを切る前提になり、その場合 Mac App Store では配れない(この点は未確認の前提)。

## 最初の版で捨てるもの

スクロール、テキスト検索、連続クリック、⌘クリック、Mission Control、Dock、ターミナルやエディタ内のリンク検出、日本語入力での絞り込みと日本語ラベル、覚えられるラベル(固定ラベル)、効果音、テーマ、Hyperkey。

## 作らない選択肢

Homerow を使い続ける(オーナーは既に PRO を持っている)。Claude Desktop で動かない点だけが痛みなら neru を試す、という選択肢もある。

作る理由は、OSS で出して人気を得るという author-fame-product のゴールと、自分で実現してみたいという動機。
