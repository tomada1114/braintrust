## 何を作るか

オーナー専用の、ローカルで動かす単語カードアプリ（Anki 代替）。目的（最初は IELTS のみ）・
トピック・目標レベルで出題範囲を絞り、カードの表面（英語の意味説明 + 答えを `___` で伏せた
穴埋め例文）を見て語を思い出し、裏面（語 + 例文 2 本）をめくって Again / Hard / Good / Easy
で自己採点する。次の出題間隔は FSRS が決める。進捗は、選んだ範囲の「今覚えている語数」
（想起確率の合計）と日次カーブで見せ、セッション終了時に今日の差分を出す。アプリの実行時に
AI は呼ばない。AI を使うのは、カードデータを事前に生成する Skill と、それを点検する Skill
だけである。Anki に対して足すのは、見た目と操作、目的・トピック別の絞り込み、進捗と
達成感の 3 つだけで、それ以外に Anki に勝る点はない。詳細は `overview.md` と `experience.md`。

## 決まっていること

日付は decisions.md への記載日。見出しは decisions.md のエントリ名で引ける。

**形態・技術**

- 最初の版はオーナー自身がローカルで動かす。公開・デプロイは後で考える（2026-09-10）。
- `nextjs-app-template` から切り出し、LLM 呼び出しの層は外す（2026-09-10）。
- 実行時に LLM を呼ばない。AI は事前のデータ準備（生成・点検）にだけ使う（2026-09-10）。
- カードは JSON ファイルとして git で管理し、Lint もそのファイルに対して回す。復習履歴と
  FSRS の状態はローカルの SQLite に置く（2026-09-10）。
- 復習間隔は FSRS の考え方で決める。評価は Again / Hard / Good / Easy の 4 段階の自己申告
  （2026-09-10）。

**カードとデータ**

- カードの項目: 表 = 英語の意味説明 + 穴埋め例文（`___`）、裏 = 語 + その語を使った例文 2 本。
  日本語は持たない。表面は毎回同じ構成で、手がかりを段階的に弱める仕組みはない
  （2026-09-10）。
- 意味説明を A1〜A2（上限 B1）の英語で書くのは生成時の目安であり、機械では確かめない
  （2026-09-10）。
- 例文 2 本は、穴埋め文とも互いとも別の場面にする（焼き直しにしない）（2026-09-10）。
- 語の同一性キーは（見出し語, 品詞）。語義では分けない（2026-09-07）。カード id もこの
  キーから決める（2026-09-11）。
- 目的（IELTS / TOEFL など）は語の属性で、1 語に複数付けられる（2026-09-07、2026-09-10 に
  複数値へ拡張）。最初の版は IELTS だけを収録する（2026-09-07 第 3 部）。
- トピックは固定の一覧から選ぶ複数タグ（2026-09-10）。一覧は次の 15 個で、増やすときは
  一覧ファイルを明示的に編集する（2026-09-11）。education / work / business-economy /
  science-technology / environment / health / media-advertising / travel-tourism /
  cities-housing / crime-law / government-society / family-relationships / culture-arts /
  food / sport-leisure
- 語のレベルは CEFR（A1〜C2）を 1 つだけ持つ自称値。目標スコアは試験ごとの換算表で CEFR に
  変換し、目標を選んだときは目標の段階とその 1 つ下を出す（IELTS 7.0 → C1 なら B2〜C1）
  （2026-09-10）。換算表は実施団体の公式対応表から作れる（`research/exam-cefr-mapping.md`）。
- 語彙は LLM 生成だけで作り、既存の公開語彙リストは配布物にも検証用の物差しにも使わない
  （2026-09-07）。
- 発音（音声・発音記号）は最初の版のカードに持たせない（2026-09-11）。
- 語彙データは、アプリのロジックから切り離せる形でアプリ内に置く（2026-09-07 第 3 部）。
  どこまで分離するかはプロダクト側で決める（下記）。

**学習の体験と進捗**（すべて 2026-09-11）

- 1 回のセッションは、期限カードを全部こなし、新規カードを上限 N 枚まで引いたら終わる。
  途中で閉じても履歴は残る。
- 毎日開くきっかけは、今日の期限カード数だけ。ストリークやポイントは持たない。
- 進捗の主指標は「今覚えている語数」。一度以上復習したカードの想起確率 R の合計で、整数に
  丸めて表示する。未復習のカードは 0 とし、未学習の残り枚数を従として添える。
- 伸びは、日次の推移カーブとセッション終了画面の差分（「今日 M 枚復習、覚えている語が
  +N」とカーブ上の今日の点）で見せる。
- 今覚えている語数とカーブは、選んでいる範囲（目的・トピック・目標レベル）に追従させる。
  範囲を外せば全体の値になる。
- 目標までの距離は、目標範囲の語群に対する「今覚えている語数 / 語群の総数」の割合だけで
  見せる。スコアの推定はしない。
- 最初の版で捨てるもの: 定着区分（未学習 / 学習中 / 定着）、ストリーク・ポイント、スコア
  推定、節目の演出、トピック別グラフの一覧、忘れかけ語の一覧。

**カードデータの準備（生成 Skill・点検 Skill・Lint）**

- 生成と点検は別の Skill にする。一度に全量を作らず、足りない範囲を回すたびに埋める
  （2026-09-10）。
- 最初の 1 回: environment / education / health を各 30 語前後（計 90 枚前後）、IELTS の
  B2〜C1（目標 IELTS 7.0 → C1 とみなす）（2026-09-11）。
- 生成 Skill の入力は（目的, トピック, CEFR の範囲, 語数）。生成の前に、既存カードの
  （見出し語, 品詞）の一覧を渡して除外させ、Lint でもキーの重複を ERROR にする。既存の語が
  新しいトピックにも合う場合は新しいカードを作らず、既存カードへのタグ追記として提案する
  （2026-09-11）。目標スコア単位で回す形は方向づけとして残っており、必要になったら足す
  （2026-09-10）。
- 点検 Skill は、カードを書いた実行とは別の独立した審査 2 本で構成する（2026-09-11）。
  - ブラインド解答: 表面だけを見せ、当てはまる語をすべて挙げさせる。答え以外にも妥当な
    候補が出たら FIX とし、絞り込む案を添えさせる。
  - 観点レビュー: 言い換えによる答えの漏れ、例文の質、言い換えで骨格を隠した焼き直し、
    2 本の例文の重複、同義語の重複。
  - 判定は FIX / DROP に確信度を添え、違反のあったカードだけを返させる。DROP は勧告で、
    最終判断はメイン側が持つ。判定を覆したときは理由を付けてオーナーに報告する。枚数に
    かかわらず毎回回す。
- 既存カードを直すときは、同じ id のカードを上書きし、FSRS の状態を引き継ぐ。変更の前後は
  git diff で読む。答えの語そのものが変わる修正は新しいカードとし、古いカードは退役扱いに
  する（復習履歴は SQLite に残す）（2026-09-11）。
- Lint のチェック項目（2026-09-10）: 語数の上限、答えの漏れ（表面に答えの語やその変化形が
  出ている）、例文が答えの語を使っていない、例文が穴埋め文の焼き直し、空欄マーカーがない。
  判断の要る点（一意性、例文の自然さ）は点検 Skill に任せる。
- Lint の閾値の初期値（2026-09-11）: 意味説明 + 穴埋め例文の合計 ≤40 語、穴埋め例文 ≤20 語、
  答えの語 ≤5 語、例文それぞれ ≤12 語（超えたら ERROR）、例文が 8 語を超えたら WARN。
  形のチェックとして `...` と `…` の禁止、どの項目にも日本語（CJK）を含まないこと、
  `___` の有無も入れる。閾値は設定の 1 か所に置き、運用しながら変える。

**続けるかどうかの判定**

- 最初の 90 枚前後が一巡する頃（使い始めて約 4 週間）に振り返る。範囲の絞り込みを一度も
  変えていない、または進捗の表示が続ける理由になっていないなら、Anki の Vocabulary デッキに
  戻る。続かなかったこと自体は判定に使わない。戻るときはカード JSON を CSV にして Anki に
  取り込む（2026-09-11）。判定するのはオーナーで、プロダクト側の実装の仕事ではない。
  ただし、範囲の選択が変わったかを後から確かめられるようにしておくと判定しやすい。

## 決まっていないこと

**プロダクト側リポジトリで決める（2026-09-11 に braintrust で仕分けた）**

- 新規カードの 1 日上限 N の初期値。10 枚程度を想定しているが、値は決めていない。
- 日次カーブの値を日ごとのスナップショットで持つか、ReviewLog（復習前の stability などを
  持つ）から過去の R を再計算するか。どちらでも実装できる（decisions.md 第 5 部）。
- 定着区分と節目の演出を、いつ足すか。使ってみてから判断する。
- FSRS オプティマイザをいつ使い始めるか。数百件以上の復習履歴が溜まってからの利用が推奨
  されており、最初は既定のパラメータで足りる（`research/spaced-repetition-fsrs.md`）。
- 将来のライブラリ化に備えて、カードデータをどこまで分離しておくか。
- 熟語・フレーズを入れるときの同一性キー（見出し語 + 品詞のままでよいか）。
- ブラインド解答で、どこまでを「妥当な候補」と数えるか（語形の違い、レジスターの違い）。
  最初の 1 回の結果を見て調整する。

**handoff を書く途中で見つかった隙間（braintrust では議論していない。プロダクト側で決める）**

- FSRS のライブラリの選定。決まっているのは「FSRS の考え方で決める」ことまでで、ts-fsrs
  （TypeScript、MIT）は自然な候補だが、明示的な決定ではない。
- 生成 Skill・点検 Skill・Lint をどこに置くか（プロダクト側リポジトリの `.claude/skills/`
  など）と、Lint の実装言語。
- カード JSON のファイルの分け方（1 ファイルにまとめるか、トピック単位か、1 カード
  1 ファイルか）とスキーマの細部。
- 固定一覧にないトピックのタグを Lint で弾くか。固定一覧の目的（表記揺れを防ぐ）からは
  自然だが、決定としては記録していない。
- 退役扱いにしたカードを、「今覚えている語数」や未学習の残りの集計から外すか。
- UI の言語（テンプレートは next-intl で en / ja を持つ）。カードの中身が英語のみである
  ことは決まっている。

## 制約

- 実行時に LLM を呼ばない。実行時の API 費用は発生しない前提で作る。
- ローカル専用、個人用。ログイン・同期・公開は最初の版の範囲外。
- 語彙は LLM 生成だけで作る。既存の公開語彙リスト・辞書データを持ち込まない。帰属表示や
  ShareAlike の義務を発生させないための決定（2026-09-07）。
- カードに日本語を持たない。
- 最初の版は IELTS の語だけを収録する。スキーマは、目的・トピックを後から足しても変わら
  ない形にする。
- 点検は、カードを書いた実行とは別の独立した実行で、枚数にかかわらず毎回回す。
- 生成・点検の実行環境の費用について、記録された制約はない。
