# english-vocab-app

オーナー専用のシンプルな単語カードアプリ。目的（IELTS / TOEFL など）とトピックで
学習範囲を絞り込み、英語の意味説明と穴埋め例文から語を思い出し、めくって自己採点する。
評価に応じて FSRS が次の復習間隔を決める。カードデータは AI で事前に生成・点検し、
アプリの実行時には AI を呼ばない（decisions.md 第 4 部 2026-09-10「アプリに AI を
組み込まない。AI は事前のデータ準備にだけ使う」）。

## 誰の何の困りごとか

- 対象: 試験のために英単語を覚えようとして、続かずに何度も離脱してきた学習者。
  2026-09-07 のヒアリング時点ではオーナー自身がこの層で、IELTS Overall 6.5、体感 6.0。
- 困りごと（2026-09-07 のヒアリングで観測された事実。事実としては今も残る）:
  - **産出側が苦しい。** 受容側も困るが、Writing / Speaking で語が出てこないほうが苦しい。
  - **続かない。数日でやめる。**
  - **覚えたはずなのに使えない。**
  - **訳や例文が薄い、または不自然。**
  - **詰め込み感が強く、覚えること自体が辛くてモチベーションが上がらない。**
  - **単語だけを覚えても「マッピング」ができない。** 文脈から切り離された語は定着しない。
  - 学習曲線のようなものを取り入れられるとよい、という要望。
- 2026-09-10 の方針転換で、対象はオーナー自身に絞った個人用の道具になった。他の学習者に
  同じ痛みが広く存在するかは、もう検討の対象にしない（decisions.md 第 4 部 2026-09-10
  「アプリに AI を組み込まない」の「承知した上での割り切り」: 個人用の道具として作るので
  差分は問わない）。

## 実在する痛みか

一人称の痛みであり、代替手段を 3 系統試してすべて離脱した履歴がある（2026-09-07 時点）。

- **mikan / abceed 系**: 「単語と意味だけなので、使える実感がない」
- **Anki / Quizlet などのカード型**: 「自分で作るのがあれすぎて」。素材作成コストで脱落
- **書籍の単語帳**: 「進捗管理とか、そもそも記憶テストとかもできないから進捗の実感がわかないし、達成感もないし、続かなかった」

代替手段で我慢できている状態ではない。ただし個人用の道具として作ると決めた以上
（decisions.md 第 4 部 2026-09-10）、この痛みが他の受験者一般にどれだけ存在するかは
論点として扱わない（open-questions.md「解決済み・消滅」参照）。

## 既存プロダクトとの違い

- 既存: 最も近いのはオーナー自身が `tomada-routine` リポジトリで運用している Anki の
  Vocabulary デッキ（`.claude/skills/anki-vocabulary/`、2026-09-10 時点で 110 枚）。
  カード形式の手本でもある。ほかに mikan / abceed / Quizlet など既存の単語・カードアプリがある。
- 足りない点: Anki は見た目と操作を自分好みに変えられず、目的（IELTS / TOEFL など）や
  トピック（病院、環境など）で出題範囲を絞り込む仕組みも、進捗と達成感を自分好みに
  見せる仕組みも持たない（decisions.md 第 4 部 2026-09-10「自前アプリで Anki に足すもの:
  見た目と操作、目的・トピック別の絞り込み、進捗と達成感」）。Anki は FSRS モードで
  「推定総知識量」を持ち、統計画面でデッキや検索で絞ることもできる。ただし学習画面
  とは別の画面であり、目的・トピック・目標レベルという軸に揃えた表示とセッション
  終了時の差分は持たない（出典: https://docs.ankiweb.net/stats.html）。
- 差分: 自前で作り込むのはこの 3 つ（見た目と操作、目的・トピック別の絞り込み、
  進捗と達成感）に限る。**自分の意見・自分の文で語を使う自由記述の産出練習と、
  それに対する LLM の添削という、かつての唯一の差別化要素は、オーナー自身の選択で
  なくなった。** 実行時に AI を組み込まないシンプルな形を優先した結果である
  （decisions.md 第 4 部 2026-09-10「アプリに AI を組み込まない」）。率直に言えば、
  現実的な代替は Anki の Vocabulary デッキそのものであり、このアプリが Anki に勝る点は
  上記 3 つの作り込みだけである。その 3 つが要らないなら Anki で足りる
  （`open-questions.md`「そもそも作るか」）。

## 何を作るか（現時点の像）

- 形態: オーナーが自分のローカル環境で動かす Web アプリ。
  `~/ghq/github.com/tomada1114/nextjs-app-template`（Next.js 16 / TypeScript / pnpm。
  LLM 呼び出しの層は外す）を元に作る。公開・デプロイは後で考える
  （decisions.md 第 4 部 2026-09-10「オーナー自身がローカルで動かす自前アプリにする。
  デプロイは後で考える」「アプリは nextjs-app-template から切り出して作る」）。
- 中核の体験: 目的・トピック・目標レベルで範囲を選び、表面（英語の意味説明 + 穴埋め例文）
  を見て頭の中で語を思い出し、裏面（語 + 例文 2 本）をめくって Again / Hard / Good / Easy
  で自己採点する。評価に応じて FSRS が次の出題間隔を決める。進捗は選択範囲の
  「今覚えている語数」（想起確率の合計）と日次カーブで見せ、セッション終了時に
  今日の差分を出す（decisions.md 第 5 部 2026-09-11）。詳細は `experience.md`。
- AI の位置づけ: **実行時には呼ばない。** AI が担うのは、カードデータを事前に生成する
  Skill と、生成後に点検・修正する Skill だけ（decisions.md 第 4 部 2026-09-10
  「アプリに AI を組み込まない。AI は事前のデータ準備にだけ使う」「カードデータは
  生成用の Skill を回して足りない範囲を埋め、生成後に点検・修正用の Skill を通す」）。

## 語彙データについて分かっていること

- カードは JSON ファイルとして git 管理し、Lint もファイルに対して回す。復習履歴と
  FSRS の状態はローカルの SQLite に置く（decisions.md 第 4 部 2026-09-10「カードデータは
  JSON ファイルで git 管理し、復習履歴はローカルの SQLite に置く」）。
- カードの形: 表 = 英語の意味説明（A1〜A2、上限 B1 は生成時の目安にすぎず機械では
  確かめない）+ 答えを `___` で伏せた穴埋め例文。裏 = 語 + その語を使った例文 2 本。
  日本語訳は持たない（同 2026-09-10「カードの形: 表は英語の意味説明と穴埋め例文を
  常に両方、裏は語と短い例文」「意味説明の語彙レベル（A1〜A2、上限 B1）は生成時の
  目安にとどめ、機械では確かめない」「カードの項目は、表 = 英語の意味説明 + 穴埋め
  例文、裏 = 語 + 例文 2 本。日本語は持たない」）。
- 語のレベルは CEFR 6 段階を 1 つだけ持つ自称値。目標スコア（IELTS 7.0 など）は
  試験ごとの換算表で CEFR に変換し、出題は目標の段階とその 1 つ下を出す。換算表の
  出典は `research/exam-cefr-mapping.md` で確認中（同 2026-09-10「語のレベルは CEFR 6
  段階で 1 つだけ持ち、目標スコアは試験ごとの換算表で CEFR に変換する。出題は目標の
  段階と 1 つ下」「語のレベル付けは自称でよい」）。
- 目的（IELTS / TOEFL など）は語に複数持たせる属性、トピック（病院、環境など）は
  固定の一覧から選ぶ複数タグ（同 2026-09-10「目的は語の属性として複数持てる。
  トピックは固定の一覧から選ぶ複数タグにする」）。固定一覧の中身と最初の 2〜3
  トピックの選定は未決（`open-questions.md`）。
- 語の同一性のキーは見出し語 + 品詞（第 1 部 2026-09-07「語の同一性のキーは
  『見出し語 + 品詞』とする」）。将来は熟語やフレーズも扱う想定だが、その際の
  同一性キーの持ち方は未決（`open-questions.md`）。
- 最初の生成 Skill は IELTS の 2〜3 トピック × 各 30 語前後（合計 60〜90 枚）を回す
  （decisions.md 第 4 部 2026-09-10「生成 Skill の最初の 1 回は、IELTS の 2〜3
  トピック × 各 30 語前後とする」）。
- Lint で語数・文字数の上限、答えの漏れ、例文が答えの語を使っていない、例文が
  穴埋め文の焼き直し、空欄マーカーの欠落を機械的に弾く。答えが一意に決まるか・
  例文が自然かといった判断の要る点は点検用の Skill に任せる（同 2026-09-10「Lint は
  語数・文字数に加え、判断の要らない形のチェックまで含める」）。

## 最初の版で捨てるもの

- 自由記述の産出練習と、それに対する LLM の添削・講評（旧 第 2 部の決定）。実行時に
  AI を使わないという決定でまるごと外れた（decisions.md 第 4 部 2026-09-10「アプリに
  AI を組み込まない」の無効化リスト）。
- 手がかりを 3 段階に弱めていく仕組み。カードの表面は毎回同じ構成になる
  （同 2026-09-10、同無効化リスト）。
- 公開・デプロイ。ローカルで自分だけが動かせればよい（同 2026-09-10「オーナー自身が
  ローカルで動かす自前アプリにする。デプロイは後で考える」）。
- 捨てる細部: 定着区分、ストリーク・ポイント、スコア推定、節目の演出
  （decisions.md 第 5 部 2026-09-11）。進捗と達成感そのものは最初の版に含める
  （下記「何を作るか」）が、上記の細部は含めない。

## 作らない選択肢

作らなければ、オーナーは Anki の Vocabulary デッキを使い続けることになる。Anki は
間隔反復・統計・同期をすでに持ち、実際に 110 枚を運用してもいる
（decisions.md 第 4 部 2026-09-10）。それでも自前アプリを選んだ理由は、見た目と操作の
カスタマイズ、目的・トピック別の絞り込み、進捗と達成感の自分好みの見せ方という 3 つに
限られる（同「自前アプリで Anki に足すもの」）。裏を返すと、この 3 つが実際には効かない
と分かれば、作らない選択肢（Anki のまま続ける）が正しくなる。これは検証されていない
前提であり、`open-questions.md`「そもそも作るか」に残す。個人用の道具であるため市場での
差別化は問わない。旧 第 2 部にあった「自由記述の産出練習という空白を埋める」という
作る理由は、オーナー自身の選択でなくなっている。
