# small-talk-trainer — 決定の記録

## 2026-09-06 核は練習装置

- 決定: 核は「練習装置」であって「雑談相手」ではない。
- 理由: 会話は手段であり、練習を短く区切り次にやることを決め、引き出しの外の表現を差し出すことが目的(Claude の指摘、owner 確認済み)。
- 却下した案: 雑談相手としての自然さを同等に重視する案 — 既製品の劣化コピーになる。

## 2026-09-06 入力の形

- 決定: 候補(レベル別 2〜3 個)から選び、そのあと自分の言葉で言い直して送る(変えなくても可)。
- 理由: 引き出しの外の表現に触れつつ、産出の要素を残すため。
- 却下した案: 純粋な選択式 — 自分で英文を組み立てる力が鍛えにくい(Claude の指摘)。
- 却下した案: 日本語で言いたいことを出して英語化を選ぶ — 日本語入力の手間がかかる。
- 却下した案: セッションごとにモードを切り替える — 最初の版には重い。

## 2026-09-06 音声入出力の扱い

- 決定: 音声入力はやらない。読み上げ(TTS)は簡単にできるなら入れる(ブラウザの speechSynthesis なら追加コストなしという Claude の解釈)。
- 理由: 音声入力の実装難度が大きい一方、TTS は既存のブラウザ機能で低コストに実現できる可能性があるため。
- 却下した案: 音声で話す・聞く — 実装難度が大きい。
- 却下した案: テキストで始めて音声は後で — 音声入力自体を当面やらないので不要。

## 2026-09-06 セッションの終わり方

- 決定: 場面の達成条件(例: 初対面の相手の週末の予定を聞き出し、自分の予定も伝える)でセッションを終える。
- 理由: 達成条件のほうが会話の自然さを保ったまま終了条件を定義できる。
- 却下した案: ターン数・時間 — スコアが別途要る。
- 却下した案: 使うべき表現の消化 — 会話が不自然になりやすい。

## 2026-09-06 最初の版の範囲

- 決定: 最初の版は「短いセッション + 候補付き入力 + 会話後の振り返り・添削(コーチ)」に絞る。スコア・ロードマップは後回し。場面は AI 任せでランダム、または過去の会話・シナリオを踏まえてある程度ランダムに候補から選ぶ。
- 理由: スコア・ロードマップはモチベーションのために欲しいが最初から要るものではない。
- 却下した案: シナリオ・ドリルのライブラリを最初から用意する — コンテンツ作りの比重が大きくなりすぎる。

## 2026-09-06 エージェント構成

- 決定: 会話エージェント 1 本 + コーチエージェント 1 本。コーチは最初から欲しい(会話全体の添削)。コーチはターンごとに口を挟む役ではなく、セッション終了後に会話全体を見て添削する役(Claude の解釈)。
- 理由: セッション終了後にまとめて添削することで、会話の自然さと実装のシンプルさを両立できる。
- 却下した案: ターンごとにコーチが介入 — 毎ターン 2 呼び出しが必要になり、遅延とコストが倍になる。

## 2026-09-06 Claude Agent SDK への非依存

- 決定: Claude Agent SDK に依存させない。
- 理由: サブスク認証での利用が規約上グレーであり、別枠課金がいつ再開されてもおかしくない(research/claude-agent-sdk-subscription-terms.md 参照)。最初の版に必要なのは呼び出し 2 本で、Agent SDK のハーネス(ファイル操作、bash、サブエージェント)は使わない。
- 却下した案: Agent SDK + API キー — Claude API は呼び出しごとに課金されるので基本候補にしない。
- 却下した案: Agent SDK + サブスク OAuth — グレーゾーンかつ方針変更リスクがある。

## 2026-09-06 実行形態・言語

- 決定: ローカルサーバー + ブラウザで実行する。言語は TypeScript(サーバーと UI が同じ言語、読み上げはブラウザで行う)。
- 理由: サーバーと UI を同じ言語で統一でき、ブラウザの読み上げ機能をそのまま使える。
- 却下した案: ターミナル CLI — UI と読み上げが扱いにくい。
- 却下した案: デスクトップアプリ — 個人の練習ツールには過剰。
- 却下した案: Python — UI は別途用意する必要がある。

## 2026-09-06 モデル・ベンダーの方針

- 決定: まず無料枠を使う。Claude API は呼び出しごとに課金されるので基本候補にしない。収益化して本番公開する前提になったら有料 AI(Agent SDK 系を含む)もあり。具体的なモデル・ベンダーは今回は未決定とし、候補も列挙せず、リサーチ(docs/landscape/)から選ぶ。
- 理由: 個人の練習用途では無料枠で十分に検証でき、コストをかけずに始められるため。
- 却下した案: Gemini 無料枠で始めると今決める — 無料枠ではデータが製品改善に使われる点を含め、調査してから判断すべき。
- 却下した案: 有料で始めると今決める — まず無料枠という方針に反する。
