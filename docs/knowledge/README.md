# knowledge

複数のアイデアに共通して効く知識のうち、LLM / エージェント基盤ではないものを置く場所。
例: 学習アプリのゲーミフィケーション。LLM / エージェント基盤は `docs/landscape/` に置く。
個々のアイデアに閉じた調査は `docs/plan/<idea-slug>/research/` に置く。

## ファイル名

`YYYY-MM-<topic>.md` の形式。日付は調査を実施した年月。更新は既存ファイルの書き換えではなく、
新しい日付のファイルを追加する。書式は `docs/plan/_templates/research.md` に従う。

## 読み方と更新

`docs/landscape/README.md` と同じ。ファイル名の日付を先に見る。最新ファイルが 3 ヶ月より古ければ
そのまま信用せず、使う前に更新を提案する。確度と「グレーゾーン・未確認」の節を結論と同じ重さで読む。
特定のアイデアの決定はここに書かず、そのアイデアの decisions.md に書く。
