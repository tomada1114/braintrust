# landscape

LLM / エージェント基盤についての事前調査を置く場所。個々のアイデアの調査
（`docs/plan/<idea-slug>/research/`）と違い、どのアイデアにも共通して効く
前提知識をまとめる。ベンダー API、料金体系、エージェント向け SDK、
データの取り扱いの規約など。

## ファイル名

`YYYY-MM-<topic>.md` の形式。例: `2026-09-vendor-apis.md`

日付は調査を実施した年月。更新は既存ファイルの書き換えではなく、新しい日付の
ファイルを追加する。過去の判断がどの時点の情報に基づいていたかを追えるようにする。

## 読み方

1. まずファイル名の日付を見る。中身より先に、いつ時点の情報かを確認する。
2. 最新ファイルが 3 ヶ月より古ければ、そのまま信用しない。使う前に更新を提案する。
3. 各記述の確度（高 / 中 / 低）と出典日付を見る。「グレーゾーン・未確認」の節は
   結論と同じくらい重要で、そこに触れる論点は原典で裏を取ってから進める。

## 更新

オーナーが調査をやり直すことで更新する。Claude 側からは、古いファイルを参照
しようとした時点で更新を提案するところまで。勝手に大規模調査を始めない。
